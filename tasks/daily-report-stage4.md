# 日报任务 - 阶段四：警报管理

> ⚠️ **无需重启警报器引擎**：引擎支持热加载（每60秒自动扫描 `rules/` 目录），新增或修改的规则文件会自动生效。**禁止执行 `pm2 restart btc-alert` 或任何重启命令。**

此任务为日报工作流的第四阶段，负责警报规则的全生命周期管理。

---

## 触发方式

- 由阶段三结束后触发
- 接收标准化的周期状态信息

---

## 日志文件

**所有阶段共用同一个日报进程日志文件：**

路径：`logs/daily-report-process.log`

格式：追加模式，记录阶段四的开始、结束、警告、错误。

**异常标识规则：**

| 级别 | 标识 | 含义 |
|------|------|------|
| **警告** | `⚠️ WARN` | 不影响流程继续执行 |
| **错误** | `⛔ ERROR` | 可能影响后续阶段 |

### A.4 创建复盘 cron 任务

**周期已归档 + 警报已清零 → 创建 24h 后触发的独立复盘任务。**

#### A.4.1 计算复盘参数

```bash
# 从周期路径提取周期 ID
CYCLE_ID=$(basename ${CYCLE_DIR})   # 如 cycle-20260514-001

# 复盘触发时间 = 当前时间 + 24h
REVIEW_AT=$(date -d "+24 hours" --iso-8601=seconds)

# 复盘报告输出文件名
REVIEW_DATE=$(date -d "+24 hours" +%Y%m%d)
REVIEW_TIME=$(date -d "+24 hours" +%H%M)
OUTPUT_NAME="review-BTC-${REVIEW_DATE}-${REVIEW_TIME}"
```

#### A.4.2 创建 cron 任务

```json
{
  "name": "review-${CYCLE_ID}",
  "agentId": "july",
  "schedule": {
    "kind": "at",
    "at": "${REVIEW_AT}"
  },
  "payload": {
    "kind": "agentTurn",
    "message": "周期路径: archived/${CYCLE_ID}\n币种: BTC\n归档时间: $(date --iso-8601=seconds)\n请读取 tasks/trade-review.md 对该周期执行独立深度复盘。",
    "timeoutSeconds": 900
  },
  "sessionTarget": "isolated",
  "deleteAfterRun": true,
  "delivery": { "mode": "none" }
}
```

**日志埋点：**
```
[$NOW] [阶段四] 📋 复盘cron已创建 | 任务: review-${CYCLE_ID} | 触发时间: ${REVIEW_AT} | 输出: learnings/${OUTPUT_NAME}.md
```

#### A.4.3 检查下次日报触发时间（空档期填补）

**问题说明：** 周期归档后，可能距离下次BTC日报定时触发（09:00 / 21:00 GMT+8）还有很长时间。这期间没有新周期，市场变化无法及时覆盖。本步骤在归档后检查空档期，必要时提前拉起新周期。

**执行逻辑：**

```
1. 通过 cron(list) 查询 BTC 日报任务（july-btc-morning-v2, july-btc-evening-v2）
2. 从每个任务的 state.nextRunAtMs 找到最近的下次触发时间
3. 计算距离当前时间的秒数差
4. 判断是否需要临时拉起新周期
```

**决策逻辑：**

| 条件 | 动作 |
|------|------|
| 无BTC日报cron任务（morning和evening都不存在） | → 创建临时cron，10分钟后触发 |
| 下次触发时间距现在 > 3600秒（> 1小时） | → 创建临时cron，10分钟后触发 |
| 下次触发时间距现在 ≤ 3600秒（≤ 1小时） | → 无需操作，等待下次正常触发 |

**步骤说明：**

1. 使用 `cron(action="list")` 工具获取所有定时任务列表
2. 查找 `july-btc-morning-v2` 和 `july-btc-evening-v2` 的任务
3. 从每个任务的 `state.nextRunAtMs` 字段获取下次触发时间（毫秒时间戳）
4. 取最近的一个：`NEXT_AT_MS = min(morning.nextRunAtMs, evening.nextRunAtMs)`
5. 计算秒数差：
```bash
NOW_EPOCH=$(date +%s)
DIFF_SECONDS=$(( (NEXT_AT_MS - NOW_EPOCH * 1000) / 1000 ))
```
或直接从两个任务中解析最近的时间：
```bash
# 使用 date 获取当前时间戳
NOW_TS=$(date +%s)
# 如果 NEXT_AT_MS 已知
DIFF=$(( (NEXT_AT_MS / 1000) - NOW_TS ))
```

6. 如果满足触发条件（无任务或 DIFF > 3600），使用 `cron(action="add")` 创建临时日报任务：

```json
{
  "name": "interim-btc-${CYCLE_ID}",
  "schedule": {
    "kind": "at",
    "at": "$(date -d "+10 minutes" --iso-8601=seconds)"
  },
  "payload": {
    "kind": "agentTurn",
    "message": "开始执行日报任务。请按顺序执行日报全四阶段：\n1. 读取 tasks/daily-report-stage1.md 执行数据获取\n2. 读取 tasks/daily-report-stage2.md 执行技术分析\n3. 读取 tasks/daily-report-stage3.md 执行仓位管理\n4. 读取 tasks/daily-report-stage4.md 执行警报管理\n每个阶段完成后自动进入下一阶段，最终输出全流程摘要。"
  },
  "sessionTarget": "isolated",
  "deleteAfterRun": true,
  "delivery": { "mode": "none" }
}
```

**日志记录（已触发）：**
```
[$NOW] [阶段四] 🔄 空档检测 | 下次日报触发: $(date -d @$((NEXT_AT_MS/1000)) '+%Y-%m-%d %H:%M:%S') | 间隔: ${DIFF_SECONDS}s | 超过1小时/不存在 → 创建临时日报任务 10分钟后触发
[$NOW] [阶段四] 🔄 interim-btc-${CYCLE_ID} 已创建 | 触发时间: $(date -d "+10 minutes" '+%Y-%m-%d %H:%M:%S')
```

**日志记录（已跳过）：**
```
[$NOW] [阶段四] 🔄 空档检测 | 下次日报触发: $(date -d @$((NEXT_AT_MS/1000)) '+%Y-%m-%d %H:%M:%S') | 间隔: ${DIFF_SECONDS}s | 不足1小时，等待正常触发
```

**注意事项：**

- `deleteAfterRun: true` 确保临时任务执行一次后自动删除，不影响正常定时任务
- `delivery: { mode: "none" }` 避免发送通知到频道（和正常日报任务保持一致）
- 临时任务的触发消息与正常日报任务完全一致，确保执行完整的四阶段流程
- 如果 cron list 返回的任务中没有 `july-btc-morning-v2` 或 `july-btc-evening-v2`（例如被误删），按「不存在」处理，同样创建临时任务

### B.4 罗列所有有价值的警报候选

**这个步骤是「发散」阶段：通读日报，尽可能收集所有值得设立的警报。**

**从日报中提取三类警报候选：**

| 警报类型 | 说明 |
|---------|------|
| **上方价格警报** | 阻力位突破、入场触发价格（向上方向） |
| **下方价格警报** | 支撑位跌破、入场触发价格（向下方向） |
| **非价格警报** | 交易量、波动率、持仓量、多空比、资金费率等 |

**不要局限于固定来源，而是从整篇报告中理解并提炼。**

日报的多个部分都可能提供警报线索：
- 价格行为分析 → 趋势判断、关键位置
- 行情推断 → 支撑/阻力位、值得关注的行为
- 仓位操作建议 → 入场条件、触发价格

**示例输出（候选列表）：**

```
候选警报列表（共 N 个）：

上方价格警报候选：
  - xxx
  - xxx

下方价格警报候选：
  - xxx
  - xxx

非价格警报候选：
  - xxx
  - xxx
```

**⚠️ 何时设定非价格类警报？**

每次警报管理时，必须主动评估是否需要设定此类警报。判断依据：

| 市场现象 | 可能的警报类型 |
|---------|---------------|
| 交易量异常放大或萎缩 | 交易量异动警报 |
| 价格在窄幅区间长时间震荡 | 波动率收窄警报（可能预示突破） |
| 短时间内剧烈波动 | 振幅警报 |
| 连续多根同向K线 | 趋势加速警报 |
| 持仓量OI快速增加或减少 | 持仓量变化警报 |
| 多空比发生明显反转 | 多空比反转警报 |
| Taker买卖比偏离常态 | Taker买卖比警报 |
| 资金费率异常（过高或过低） | 资金费率警报 |
| ... | **发散思考，不限于上述示例** |

**⚠️ 重要：发散思维**

以上仅为示例，**切勿局限于这些场景**。每次分析时，应主动思考：

- 当前市场有什么**异常或值得关注的现象**？
- 这些现象如果**持续或反转**，会对持仓产生什么影响？
- 是否有**其他维度**的数据可以提前预警？

**警示**：不要每次只设定价格警报。如果市场处于低波动期，价格警报可能长期不触发，但交易量、波动率的变化可能在提前发出信号。忽略这些信号可能导致错过关键转折点。

**如果候选列表中只有价格警报，说明思维已固化，需要主动打破。**

**日志记录：**
```
[$NOW] [阶段四] 警报候选: 上方价格 X 个 / 下方价格 X 个 / 非价格 X 个 / 共计 X 个
```

### B.5 筛选警报（符合限制）

**这个步骤是「收敛」阶段：从候选中选出最有价值的警报。**

**警报数量限制：**

| 类型 | 最大数量 | 说明 |
|------|---------|------|
| **价格警报** | **≤6 个价位** | 单个规则文件可包含多个价位（上方/下方不限） |
| 非价格警报 | **≤2 个** | 独立规则文件 |
| **总计** | **≤3 个规则文件** | 1个多价位规则 + ≤2个非价格规则 |

**筛选原则（价位）：**

| 优先级 | 选择依据 | 说明 |
|-------|---------|------|
| **高** | 触发后需要执行操作的价位 | 入场触发价、止损/止盈位 |
| **中** | 报告明确指出的关键支撑/阻力 | 技术分析关键位置 |
| **低** | 整数关口、斐波那契等参考价位 | 心理关口，有参考价值 |

**⚠️ 关键变化：**

- **废弃**「上方1个/下方1个」的筛选限制
- **改为**「最有价值的 ≤6 个价位打包进一个规则文件」
- 单次触发可传递组合信息（多个价位同时被触发）

**示例筛选**（当前价格 $78,500）：

```
候选价位（共8个）：
  上方：$79,443 (旗形顶部)、$80,000 (整数关口)、$81,500 (前高)、$82,000 (心理压力)
  下方：$77,500 (关键支撑)、$74,980 (情景C目标)、$73,596 (深度支撑)、$72,000 (整数关口)

筛选逻辑：
  ✅ $79,443 - 触发做多B（高优先级）
  ✅ $77,500 - 触发情景C（高优先级）
  ✅ $74,980 - 止盈/目标位（中优先级）
  ✅ $81,500 - 趋势反转点（中优先级）
  ✅ $80,000 - 心理关口（低优先级）
  ✅ $73,596 - 深度支撑（中优先级）
  
  ❌ $82,000 - 距离太远（$3,500），放弃
  ❌ $72,000 - 距离太远（$6,500），放弃

最终警报（打包为1个多价位规则）：
  - 多价位监控规则（6个价位）
  - 非价格规则1（如交易量异动）
  - 非价格规则2（如持仓量变化）
```

**日志记录：**
```
[$NOW] [阶段四] 筛选结果: 价格价位 X 个 / 非价格 X 个 / 共计 X 个规则文件
[$NOW] [阶段四] 最终价位列表: [价位及描述]
[$NOW] [阶段四] 最终非价格列表: [警报描述]
```

### B.5.5 分配价位确认策略（防假突破）

**⚠️ 必做步骤：为每个入选价位分配 `confirmPolicy` 和 `confirmMs`。**

筛选出最终价位列表后，不能直接创建规则——必须先为每个价位决定确认策略。这是防止假突破的关键。

**确认策略速查表：**

| 价位类型 | 推荐策略 | `confirmMs` | 理由 |
|---------|---------|------------|------|
| 止损位 (SL) | `instant` | 0 | 最后防线，不能延迟 |
| 止盈位 (TP1/TP2) | `touch` | 3-5 min | 到了就止盈，短暂确认即可 |
| 入场触发位（开仓/加仓） | `hold` | 15-20 min | **假突破高发区**，必须等待站稳 |
| 关键支撑/阻力（有 action） | `hold` | 10-20 min | 突破/跌破确认后才有操作意义 |
| 整数关口（心理位） | `deep_hold` | 20-30 min | 容易被假突破，且操作性弱 |
| 远处观测位（前高/前低等） | `deep_hold` | 20-30 min | 不急，长确认后再分析 |

**分配决策流程：**

```
对每个最终价位，问自己：
1. 这个价位被"摸一下"的概率有多大？（整数关口 > 结构位 > TP/SL）
2. 如果假突破触发了分析，会有什么后果？（入场误判 > 观测误判）
3. 触发后需要立即行动吗？（SL必须立即，入场信号需要确认）

→ 选择对应的 confirmPolicy
```

**反例（必须避免）：**

| 价位 | ❌ 错误策略 | 问题 | ✅ 正确策略 |
|------|-----------|------|------------|
| 入场触发 $77,300 | `instant` | 影线一碰就触发入场分析 → 假突破导致误入场 | `hold` (15-20min) |
| 整数关口 $80,000 | `touch` | 整数关口假突破极频繁，3分钟不够 | `deep_hold` (20-30min) |
| 止损位 $76,688 | `hold` | 止损到了必须立即触发，不能等20分钟 | `instant` |
| 14d前高 $79,490 | `touch` | 远处价格不急，触发也没有立即操作 | `deep_hold` (20-30min) |

**输出示例：**

```
最终价位及确认策略（共6个）：
  ⬆️ $77,304 (BB中轨/多头确认) → hold, 20min   [入场触发位，防假突破]
  ⬆️ $77,858 (TP1)              → touch, 3min    [止盈位，快确认]
  ⬆️ $78,500 (TP2)              → touch, 3min    [止盈位，快确认]
  ⬇️ $77,050 (多头防线)          → hold, 15min    [结构位，需站稳]
  ⬇️ $76,800 (结构弱化)          → hold, 15min    [结构位，需站稳]
  ⬇️ $76,688 (SL止损位)          → instant, 0min  [止损位，不能延迟]
```


## 核心要求

1. **⭐ 优先解析上一步消息**：从阶段三结束后传递的消息中获取周期状态和路径
2. **保底措施必须执行**：上一步消息解析失败时，从本地默认路径查找
3. **周期状态决定流程**：archived → 清零，active → 正常管理
4. **通读整篇日报**：理解分析逻辑，提炼警报意图（仅 active 状态）
5. **归档失效规则前置**：先清理，再规划（仅 active 状态）

9. **禁止 FGI 触发**：恐惧贪婪指数不适合分钟级警报
10. **使用连续数据**：K线区间而非瞬时价格（见 set-alert.md 规范）
11. **日志记录完整**：所有操作记录到 daily-report-process.log

| 检查项 | 要求 | 易错点 |

| ☐ 总计规则文件是否 ≤ 3 个？ | 1个多价位 + ≤2个非价格 | 规则过多 |

### 思维发散核对

| 检查项 | 正确做法 | 易错点 |
|-------|---------|-------|
| ☐ 候选阶段是否有发散思维？ | 主动评估交易量、波动率等维度 | 只盯着价格 |
| ☐ 候选列表是否只有价格警报？ | 必须有非价格候选 | 思维固化 |
| ☐ 触发条件是否有数据源支持？ | 参考 set-alert.md 可用 API | 无法获取数据 |

### 延迟确认核对（防假突破）

| 检查项 | 正确做法 | 易错点 |
|-------|---------|-------|
| ☐ 每个价位是否分配了 confirmPolicy？ | 按价位类型选择 instant/touch/hold/deep_hold | 全部用默认或忽略 |
| ☐ 入场触发位是否用了 hold（非 instant）？ | 入场触发必须延迟确认 | 影线触发导致误入场 |
| ☐ SL/TP 是否用了合适的短延迟？ | SL=instant, TP=touch | SL 延迟导致止损过晚 |
| ☐ 整数关口/远处价是否用了 deep_hold？ | 远处价位不急确认 | 频繁触发无意义的分析 |
| ☐ 创建规则时用了延迟确认模板（set-alert.md §13）？ | 优先使用 §13 模板 | 使用 §12 无延迟模板 |

### 规则文件核对

| 检查项 | 正确做法 | 易错点 |
|-------|---------|-------|
| ☐ 冷却时间是否 ≥ 1 小时？ | COOLDOWN_MS = 60 * 60 * 1000 | 设定过短 |
| ☐ 是否使用异步触发？ | spawn 创建隔离会话 | 使用 execSync 阻塞 |
| ☐ lifetime 是否合理？ | 根据分析设定有效期 | 永久有效或立即过期 |
| ☐ 是否使用K线数据而非瞬时价格？ | getKlines获取区间高低价 | getTicker单点比较 |

| 检查项 | 正确做法 | 易错点 |

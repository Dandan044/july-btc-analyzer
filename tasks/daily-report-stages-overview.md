# 日报任务流程衔接概览

本文档汇总各阶段的衔接关系、参数传递规范和保底措施。

---

## 流程总览

```
[定时触发]
    │
    ▼
┌─────────────────────────────────────┐
│ 阶段一：数据获取                      │
│ - 周期检测与文件夹创建                 │
│ - 实盘持仓同步                        │
│ - 市场数据获取                        │
│ - 数据挖掘报告生成                    │
│ - 数据清单 JSON 生成                  │
└─────────────────────────────────────┘
    │ spawn (传递完整参数)
    ▼
┌─────────────────────────────────────┐
│ 阶段二：数据分析                      │
│ - 解析 spawn 或保底查找               │
│ - 读取市场数据、持仓文件              │
│ - 读取历史报告                        │
│ - 分析并撰写日报                      │
└─────────────────────────────────────┘
    │ spawn (传递完整参数 + 操作预判)
    ▼
┌─────────────────────────────────────┐
│ 阶段三：仓位管理                      │
│ - 解析 spawn 或保底查找               │
│ - 读取日报、持仓文件                  │
│ - 识别操作意图                        │
│ - 执行仓位操作（如有）                │
│ - 同步持仓文件                        │
│ - 判断归档                            │
└─────────────────────────────────────┘
    │ spawn (传递周期状态)
    ▼
┌─────────────────────────────────────┐
│ 阶段四：警报管理                      │
│ - 解析 spawn 或保底查找               │
│ - 根据 cycle 状态分支执行             │
│   - archived → 警报清零              │
│   - active → 正常警报管理            │
│ - 归档失效规则                        │
│ - 罗列候选 → 筛选最终                 │
│ - 创建/保持/归档规则                  │
└─────────────────────────────────────┘
    │
    ▼
[流程结束]
```

## Spawn 消息传递规范

### 阶段一 → 阶段二

**只需传递数据清单路径，其他信息都在清单 JSON 中。**

**模板：**

```
阶段一数据获取已完成。
数据清单: active/cycle-YYYYMMDD-XXX/data-context/data-manifest-YYYY-MM-DD-HHMM.json
请读取 tasks/daily-report-stage2.md 开始阶段二分析。
```

**清单已包含：**
- 周期ID、周期状态
- 持仓文件路径
- 市场数据路径
- 数据挖掘报告路径
- 历史报告路径列表

阶段二只需读取清单即可获取所有参数，无需冗余传递。

---

### 阶段二 → 阶段三

**传递周期目录路径，阶段三从中定位日报和持仓文件。**

**模板：**

```
阶段二分析已完成。
周期目录: active/cycle-YYYYMMDD-XXX
请读取 tasks/daily-report-stage3.md 开始阶段三仓位管理。
```

**阶段三所需参数及来源：**

| 参数 | 来源 | 说明 |
|------|------|------|
| 周期目录 | spawn 传入 | 基础定位 |
| 日报文件 | `${CYCLE_DIR}/reports/btc-report-*.md` | 从周期目录定位（最新） |
| 持仓文件 | `${CYCLE_DIR}/positions.json` | 从周期目录定位（固定位置） |

---

### 阶段三 → 阶段四

**只传递周期状态和周期路径，阶段四不需要持仓状态和最近平仓信息。**

**模板：**

```
阶段三仓位管理已完成。
周期状态: [active | archived]
周期路径: [active/cycle-xxx | archived/cycle-xxx]
请读取 tasks/daily-report-stage4.md 开始阶段四警报管理。
```

**阶段四流程分析：**

| 状态 | 需要的参数 | 流程 |
|------|-----------|------|
| archived | 只需周期状态 | 直接清零所有警报 |
| active | 需周期路径 | 定位日报，正常警报管理 |

**不传递的参数：**
- 持仓状态：不影响警报管理流程
- 最近平仓：不影响警报管理流程

## 保底措施汇总

**每个阶段都必须在 spawn 解析失败时执行保底查找。**

### 保底触发条件

| 触发条件 | 处理方式 |
|---------|---------|
| Spawn 消息格式异常 | 执行保底查找 |
| Spawn 消息缺少关键参数 | 执行保底查找 |
| Spawn 消息路径不存在 | 执行保底查找 |

### 保底查找规则

| 阶段 | 保底查找 | 从保底结果推断其他路径 |
|------|---------|----------------------|
| **阶段二** | 找清单 | 清单内含所有参数 |
| **阶段三** | 找周期目录 | 日报 `${CYCLE_DIR}/reports/`，持仓 `${CYCLE_DIR}/positions.json` |
| **阶段四** | 找周期目录 | 从路径推断状态（active/archived） |

**保底查找命令：**

```bash
# 阶段二
MANIFEST=$(ls -t active/cycle-*/data-context/data-manifest-*.json | head -1)

# 阶段三
CYCLE_DIR=$(ls -td active/cycle-* | head -1)

# 阶段四
CYCLE_ACTIVE=$(ls -td active/cycle-* | head -1)
CYCLE_ARCHIVED=$(ls -td archived/cycle-* | head -1)
```

### 保底日志记录规范

**必须记录：**

```
[$NOW] [阶段X] ⚠️ WARN: Spawn 消息解析失败，使用保底路径查找
[$NOW] [阶段X] 保底路径: 周期=${CYCLE_DIR}, [其他关键路径]
```

---

## 异常处理原则

| 级别 | 标识 | 含义 | 处理方式 |
|------|------|------|---------|
| **警告** | `⚠️ WARN` | 不影响流程继续执行 | 记录日志，继续执行 |
| **错误** | `⛔ ERROR` | 可能影响后续阶段 | 记录日志，视情况决定是否继续 |

**保底措施属于警告级别：**
- spawn 解析失败 → `⚠️ WARN` → 执行保底查找 → 继续执行
- 保底查找失败 → 视情况升级为 `⛔ ERROR`

## Spawn 消息传递链（简化版）

| 传递方向 | Spawn 消息内容 | 说明 |
|---------|---------------|------|
| **一→二** | 清单路径 | 清单内含：周期ID、持仓文件、市场数据、历史报告等 |
| **二→三** | 周期目录 | 阶段三从中定位日报和持仓文件 |
| **三→四** | 周期状态 + 周期路径 | archived→清零，active→正常管理（不需要持仓状态） |

---

## 各阶段保底触发场景

| 阶段 | 触发条件 | 保底动作 |
|------|---------|---------|
| 阶段二 | 无法解析清单路径 | 找最新清单 |
| 阶段三 | 无法解析周期目录 | 找最新周期目录，从中定位日报/持仓 |
| 阶段四 | 无法解析周期状态 | 找周期目录，从路径推断状态 |

---

## 阶段四特殊说明

**阶段四流程分析：**

| 周期状态 | 流程 | 所需参数 |
|---------|------|---------|
| `archived` | 警报清零 | 只需周期状态，不需要日报 |
| `active` | 正常警报管理 | 需周期路径定位日报 |

**保底推断周期状态：**
- 路径含 `active/` → 周期状态 = `active`
- 路径含 `archived/` → 周期状态 = `archived`

---

## 核心设计原则

1. **spawn 优先，保底兜底**：每个阶段先解析 spawn，失败则保底
2. **避免冗余传递**：下游阶段本职工作的信息，上游不预判传递
3. **清单作为信息载体**：阶段一生成的清单携带所有必要信息
4. **保底路径标准化**：统一用 `ls -t ... | head -1` 找最新文件

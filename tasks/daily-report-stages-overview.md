# 日报任务流程衔接概览

本文档汇总各阶段的衔接关系、参数传递规范和保底措施。

---

## 流程总览

```
[定时触发]
    │
    ▼
┌─────────────────────────────────────┐
│ 阶段一：数据获取                      │
│ - 周期检测与文件夹创建                 │
│ - 实盘持仓同步                        │
│ - 市场数据获取                        │
│ - 数据挖掘报告生成                    │
│ - 数据清单 JSON 生成                  │
└─────────────────────────────────────┘
    │ spawn (传递完整参数)
    ▼
┌─────────────────────────────────────┐
│ 阶段二：数据分析                      │
│ - 解析 spawn 或保底查找               │
│ - 读取市场数据、持仓文件              │
│ - 读取历史报告                        │
│ - 分析并撰写日报                      │
└─────────────────────────────────────┘
    │ spawn (传递完整参数 + 操作预判)
    ▼
┌─────────────────────────────────────┐
│ 阶段三：仓位管理                      │
│ - 解析 spawn 或保底查找               │
│ - 读取日报、持仓文件                  │
│ - 识别操作意图                        │
│ - 执行仓位操作（如有）                │
│ - 同步持仓文件                        │
│ - 判断归档                            │
└─────────────────────────────────────┘
    │ spawn (传递周期状态)
    ▼
┌─────────────────────────────────────┐
│ 阶段四：警报管理                      │
│ - 解析 spawn 或保底查找               │
│ - 根据 cycle 状态分支执行             │
│   - archived → 警报清零              │
│   - active → 正常警报管理            │
│ - 归档失效规则                        │
│ - 罗列候选 → 筛选最终                 │
│ - 创建/保持/归档规则                  │
└─────────────────────────────────────┘
    │
    ▼
[流程结束]
```

## Spawn 消息传递规范

### 阶段一 → 阶段二

**必须包含的参数：**

| 参数 | 标记 | 示例 | 用途 |
|------|------|------|------|
| 周期ID | `周期ID:` | `cycle-20260419-001` | 定位周期文件夹 |
| 周期状态 | `周期状态:` | `active` | 判断是否归档 |
| 数据清单 | `数据清单:` | `active/cycle-xxx/data-context/...` | 读取 manifest |
| 持仓文件 | `持仓文件:` | `active/cycle-xxx/positions.json` | 读取实盘持仓 |
| 市场数据 | `市场数据:` | `data/YYYY-MM-DD.json` | 读取市场数据 |
| 数据挖掘报告 | `数据挖掘报告:` | `active/cycle-xxx/data-context/...` | 读取数据洞察 |
| 历史报告数 | `历史报告数:` | `X 篇` | 了解历史信息量 |

**完整模板：**

```
阶段一数据获取已完成。
周期ID: cycle-YYYYMMDD-XXX
周期状态: active
数据清单: active/cycle-YYYYMMDD-XXX/data-context/data-manifest-YYYY-MM-DD-HHMM.json
持仓文件: active/cycle-YYYYMMDD-XXX/positions.json
市场数据: data/YYYY-MM-DD.json
数据挖掘报告: active/cycle-YYYYMMDD-XXX/data-context/data-mining-YYYY-MM-DD-HHMM.md
历史报告数: X 篇
请读取 tasks/daily-report-stage2.md 开始阶段二分析。
```

### 阶段二 → 阶段三

**必须包含的参数：**

| 参数 | 标记 | 示例 | 用途 |
|------|------|------|------|
| 周期ID | `周期ID:` | `cycle-20260419-001` | 定位周期文件夹 |
| 周期状态 | `周期状态:` | `active` | 判断是否归档 |
| 日报文件 | `日报文件:` | `active/cycle-xxx/reports/...` | 读取分析报告 |
| 持仓文件 | `持仓文件:` | `active/cycle-xxx/positions.json` | 读取实盘持仓 |
| 操作建议类型 | `操作建议类型:` | `开仓/观望/...` | 预判执行类型 |
| 入场条件 | `入场条件:` | `立即入场/等待触发` | 判断是否执行 |

**完整模板：**

```
阶段二分析已完成。
周期ID: cycle-YYYYMMDD-XXX
周期状态: active
日报文件: active/cycle-YYYYMMDD-XXX/reports/btc-report-YYYY-MM-DD-HHMM.md
持仓文件: active/cycle-YYYYMMDD-XXX/positions.json
操作建议类型: [开仓/加仓/减仓/平仓/调整止盈止损/观望]
入场条件: [立即入场/等待触发]
请读取 tasks/daily-report-stage3.md 开始阶段三仓位管理。
```

**预解析优势：**
- `入场条件: 等待触发` → 阶段三可直接跳过仓位操作执行
- `操作建议类型: 观望` → 阀段三可直接跳过仓位操作执行

---

### 阶段三 → 阶段四

**必须包含的参数：**

| 参数 | 标记 | 示例 | 用途 |
|------|------|------|------|
| 周期状态 | `周期状态:` | `active` 或 `archived` | 决定执行逻辑 |
| 周期路径 | `周期路径:` | `active/cycle-xxx` | 定位报告和持仓 |
| 持仓状态 | `持仓状态:` | `有持仓 X 个` 或 `无持仓` | 了解当前持仓 |
| 最近平仓 | `最近平仓:` | `有` 或 `无` | 判断是否刚平仓 |

**完整模板：**

```
阶段三仓位管理已完成。
周期状态: [active | archived]
周期路径: [active/cycle-xxx | archived/cycle-xxx]
持仓状态: [有持仓 X 个 | 无持仓]
最近平仓: [有/无]
请读取 tasks/daily-report-stage4.md 开始阶段四警报管理。
```

**周期状态决定执行逻辑：**
- `archived` → 阀段四执行警报清零流程
- `active` → 阀段四执行正常警报管理流程

## 保底措施汇总

**每个阶段都必须在 spawn 解析失败时执行保底查找。**

### 保底触发条件

| 触发条件 | 处理方式 |
|---------|---------|
| Spawn 消息格式异常 | 执行保底查找 |
| Spawn 消息缺少关键参数 | 执行保底查找 |
| Spawn 消息路径不存在 | 执行保底查找 |

### 保底查找规则

| 参数 | 阶段二 | 阶段三 | 阶段四 |
|------|-------|-------|-------|
| 周期目录 | `ls -td active/cycle-* | head -1` | 同 | 同（优先active，备选archived） |
| 数据清单 | `${CYCLE_DIR}/data-context/data-manifest-*.json`（最新） | - | - |
| 持仓文件 | `${CYCLE_DIR}/positions.json` | 同 | 同 |
| 市场数据 | `data/YYYY-MM-DD.json`（当天） | - | - |
| 数据挖掘报告 | `${CYCLE_DIR}/data-context/data-mining-*.md`（最新） | - | - |
| 日报文件 | - | `${CYCLE_DIR}/reports/btc-report-*.md`（最新） | 同 |
| 周期状态 | 从周期路径推断（active → active） | 同 | 从路径判断或从持仓推断 |

### 保底日志记录规范

**必须记录：**

```
[$NOW] [阶段X] ⚠️ WARN: Spawn 消息解析失败，使用保底路径查找
[$NOW] [阶段X] 保底路径: 周期=${CYCLE_DIR}, [其他关键路径]
```

---

## 异常处理原则

| 级别 | 标识 | 含义 | 处理方式 |
|------|------|------|---------|
| **警告** | `⚠️ WARN` | 不影响流程继续执行 | 记录日志，继续执行 |
| **错误** | `⛔ ERROR` | 可能影响后续阶段 | 记录日志，视情况决定是否继续 |

**保底措施属于警告级别：**
- spawn 解析失败 → `⚠️ WARN` → 执行保底查找 → 继续执行
- 保底查找失败 → 视情况升级为 `⛔ ERROR`

---

## 核心设计原则

1. **spawn 优先，保底兜底**：每个阶段先尝试解析 spawn 消息，失败则保底查找
2. **参数完整传递**：spawn 消息必须包含所有必要信息，减少保底触发
3. **保底路径标准化**：所有阶段使用统一的保底查找规则
4. **日志分级记录**：保底触发时必须记录警告日志
5. **流程不中断**：保底措施确保流程能继续执行（除非关键路径缺失）

# 交易复盘任务 v2.0

由阶段四归档完毕后创建的 cron 任务触发（延迟 24h），对单个已归档周期执行独立深度复盘。任务为一次性，用完即删。

---

## 触发方式

- 由 cron job `review-{周期ID}` 在归档 24h 后自动触发
- sessionTarget: isolated | deleteAfterRun: true

**入参格式（cron payload.message）：**

```
周期路径: archived/{周期ID}
币种: {BTC 或山寨币代号}
归档时间: {ISO-8601 时间}
请读取 tasks/trade-review.md 对该周期执行独立深度复盘。
```

---

## 约束

### 必须

- **只读**：不修改 `archived/` 内任何文件
- **数据驱动**：所有判断有数据支撑，不猜测
- **诚实**：事后验证结论不明确时如实陈述
- **评级针对决策质量**：赚钱 ≠ 决策正确，亏钱 ≠ 决策错误
- **改进建议必须具体**：不说「注意风险」，说「止损应从 x% 放宽至 y%」

### 禁止

- 替主人做交易决策
- 用「感觉」「可能」「应该」式模糊结论
- 对无法验证的事下断言

---

## 输入

从 cron payload 解析周期路径，从周期目录内读取全部数据：

- `positions.json` → 交易摘要（方向、入场、平仓、盈亏、平仓类型）
- `reports/` 下全部报告 → 决策链还原
- 当前市场数据（通过 skills/btc-market-lite 或 OKX API 获取） → 事后验证

**如果 `positions.json` 中「最近平仓」为 null**：无复盘对象，记录日志后结束。

**如果 reports/ 为空**：跳过决策溯源，仅做事后验证，标注「无报告可溯源」。

---

## 复盘维度

从以下维度审视这笔交易。**哪个维度有信号就深入哪个，不必面面俱到。交叉分析，发现矛盾或联系。**

### 维度一：决策溯源

从周期内全部报告还原当时的判断链路：

- 开仓理由是什么？当时市场结构和指标状态如何支撑这个判断？
- 报告中有没有提到后来被忽略的风险信号？
- 持仓期间方向判断是否发生过变化？变化的原因是什么？
- 连续 ≥3 篇报告维持同一方向判断时（见工作区根目录 `TRADE_LESSONS.md` 确认偏误相关条目），是否存在自我强化？
- 实际入场价与建议入场价是否有偏差？偏差对盈亏比的影响？

**核心问题：在当时信息条件下，这个决策链是否自洽？**

### 维度二：事后验证

以平仓时刻为分界，对比平仓后 24h 的价格行为：

- 平仓后价格的整体走势是什么形态？继续恶化、反转、还是横盘？
- 如果止损后反转：反转发生在多久后？幅度多大？止损是否被正常波动扫出？
- 如果止盈后继续朝有利方向走：走了多远？移动止盈是否更合适？
- 如果手动平仓：触发干预的信号在事后看是否成立？

**核心问题：以 24h 马后炮视角，这个平仓是对的吗？**

### 维度三：教训提炼

结合前两个维度，提炼可复用的认知：

- 对照工作区根目录 `TRADE_LESSONS.md` 中的已知模式，这笔交易是否触发了其中某条？
- 如果触发已知模式：本次有什么新的认知增量？
- 如果未匹配任何已知模式：这是新的经验，值得写入暂存文件 `learnings/PENDING_TRADE_LESSONS.json` 吗？
- 方向判断、入场时机、止盈止损设置、仓位管理——哪个环节是这次结果的瓶颈？

**核心问题：下次遇到类似情境，应该改变什么？**

---

## 评级

对**决策质量**评级，不是对盈亏结果评级。

| 等级 | 标签 | 含义 |
|------|------|------|
| **S** | 🔴 严重错误 | 决策逻辑有缺陷，分析框架层面需要修正 |
| **A** | 🟠 可改进 | 方向可能对，但执行层面（止损/入场/仓位）有明显问题 |
| **B** | 🟡 意料之中 | 概率内的正常结果，决策和执行基本合理 |
| **C** | 🔵 不可抗力 | 超出技术分析范畴的外部冲击导致 |

**评级必须附带一句话理由，解释为什么是这个等级而不是相邻等级。**

`{COIN}` 大写币种名，`{YYYYMMDD}` 和 `{HHMM}` 为复盘生成时间。

### 报告结构

## 收尾

### 写入暂存文件（JSON 格式）

如果维度三产生了新认知（未匹配工作区根目录 `TRADE_LESSONS.md` 已知模式），追加写入 `learnings/PENDING_TRADE_LESSONS.json`。

暂存文件为 JSON 数组格式，每条教训是一个对象：

```json
[
  {
    "date": "YYYY-MM-DD",
    "title": "教训标题",
    "trigger": "简述触发本次教训的交易",
    "calibration": "提炼的新认知",
    "selfCheckQuestions": [
      "具体的自查问题1",
      "具体的自查问题2"
    ],
    "sourceCycle": "周期ID",
    "sourceReview": "learnings/review-{COIN}-{YYYYMMDD}-{HHMM}.md",
    "status": "pending"
  }
]
```

**字段说明：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `date` | string | ✅ | 触发日期 YYYY-MM-DD |
| `title` | string | ✅ | 简短标题，概括教训核心 |
| `trigger` | string | ✅ | 触发交易的简述 |
| `calibration` | string | ✅ | 提炼的新认知 |
| `selfCheckQuestions` | string[] | ✅ | 自查问题列表，至少1条 |
| `sourceCycle` | string | ✅ | 来源周期ID |
| `sourceReview` | string | ✅ | 来源复盘报告路径 |
| `status` | string | ✅ | 固定 `pending`，人工审核后改为 `approved` 或 `rejected` |

**写入方式：** 读取现有 `learnings/PENDING_TRADE_LESSONS.json`，追加新条目到数组末尾，写回文件。如果文件不存在或为空，创建包含单条目的新数组。

### ⛔ 强制约束：禁止修改 TRADE_LESSONS.md

复盘任务**绝不允许**直接写入或修改工作区根目录 `TRADE_LESSONS.md`。

原因：
1. `TRADE_LESSONS.md` 是正式的交易教训库，需要人工审核沉淀，不是复盘阶段的输出目标
2. 复盘产物统一写入 `learnings/` 下的暂存区或报告文件
3. `learnings/PENDING_TRADE_LESSONS.json` 中的教训**仅由人工**审核后提升至正式文件

## 异常

| 情况 | 处理 |
|------|------|
| payload 解析失败 | ⛔ 记录日志，结束 |
| 周期目录/positions.json 不存在 | ⛔ 记录日志，结束 |
| 最近平仓为 null | 标记「无平仓」，结束 |
| reports/ 为空 | ⚠️ 跳过决策溯源 |
| 市场数据获取失败 | ⚠️ 跳过事后验证 |

# [2026-05-16] 警报器引擎触发即归档 + 冷却机制移除 + 规则代码质量修复

## 背景

5 月 15 日晚币圈剧烈波动，七月接收到大量即时分析任务。12 小时后即时分析仍源源不断涌入。经排查发现警报器引擎陷入死亡循环：72 个活跃规则每轮狂发 80+ OKX API 请求 → 触发 429 限流 → 进程崩溃 → PM2 自动重启（累计 301 次）→ 冷却状态丢失 → TON-oi-change 规则反复触发 25 次 → 更多规则堆积。

## 症状

| 现象 | 数据 |
|------|------|
| PM2 重启次数 | **301 次**（仅过去 10 分钟窗口） |
| 活跃规则数 | **72 个**（涵盖 30+ 币种，全无活跃持仓） |
| 归档规则累计 | **786 个** |
| 429 限流错误 | 从凌晨 05:24 到上午 10:59 持续密集出现，最高单次 8 个 |
| TON-oi-change 触发 | **25 次**（每 3-10 分钟一次） |
| 即时分析 cron job | 大部分失败（context overflow / gateway restart 中断 / edit 权限错误） |
| 警报器日志文件 | **4.4MB / 28,402 行** |

## 根因分析

### 根因 1：规则生命周期设计下放给 LLM → 35% 缺失触发即销毁守卫

模板 `set-alert.md` 中有正确的 `if (this.lastTriggered > 0) return 'completed'` 守卫，但 25 个规则（35%）在生成时遗漏。触发最多的 4 个全部在缺失组：

| 规则 | 触发次数 | 有守卫？ |
|------|---------|---------|
| TON-oi-change | 25 | ❌ |
| KMNO-price-breakout | 8 | ❌ |
| TON-volume-anomaly | 7 | ❌ |
| BOME-price-monitor | 4 | ❌ |

这些规则触发后不归档，加上引擎崩溃 → `lastTriggered` 重置为 0 → 冷却白费 → 无限重触发。

### 根因 2：72 个独立 setInterval 无并发控制 → 429 限流

引擎为每个规则创建独立的 `setInterval`，500ms 打散启动，但运行后自然重叠。72 个规则同时向 OKX 发请求 → 超限 → 429 → 部分规则抛错 → 达到 5 次错误触发自愈 → 自愈 spawn 消耗更多资源 → 进程崩溃。

### 根因 3：引擎崩溃 → PM2 自动重启 → 冷启动洪水

每次崩溃重启 = 冷启动 → 加载 72 规则 → 同时开始第一轮检查 → 80+ API 请求 → 429 → 再次崩溃。间隔从凌晨的 30-60 分钟加速到上午的 2-3 分钟。

### 根因 4：4 个代码质量 bug 静默浪费 API

| Bug | 影响规则 | 机制 |
|-----|---------|------|
| `parseFloat(k[2])` 数组下标取对象属性 → NaN | ENS-price-levels | 不抛错，静默产生 $NaN |
| `{proxy, instType}` 对象传字符串参数 → `[object Object]` | BOME-taker-monitor | API 内部 fallback，不抛错 |
| `fundingData.currentRate` 用错属性名 → undefined | MEW/2Z/TURBO 等 6 个 | guard 拦截，静默返回 false |

这些 bug 从不抛异常 → 自愈系统的 `consecutiveErrors` 始终 ≤ 2 → 永远不触发自愈。

## 修复内容

### 架构改动

| 文件 | 改动 | 原因 |
|------|------|------|
| `engine.js` runRule() | 触发后直接 `archiveRule('triggered')` + `return 'stop'`，替代冷却设置 | 引擎层强制执行触发即归档，规则无法绕过 |
| `engine.js` | 注释 `triggerCooldowns` Map、`DEFAULT_COOLDOWN_MS`、冷却检查、`COOLDOWN_SET` 日志 | 冷却机制完全废弃 |
| `set-alert.md` | 删除所有生命周期设计（`COOLDOWN_MS`、`lastTriggered`、冷却检查、`lifetime()` 复杂实现、§3.2 冷却机制、§3.3 生命周期管理），替换为 `lifetime() { return 'active'; }` | 生命周期统一由引擎管理，LLM 不再参与设计 |
| `set-alert.md` §7 | 删除「提醒用户重启警报器引擎」→ 替换为热加载说明 | 引擎 60 秒自动扫描，无需重启 |
| `alt-intel-stage4.md` + `daily-report-stage4.md` | 顶部添加 banner：「无需重启引擎 + 禁止 pm2 restart」 | 防止 LLM 在阶段四执行重启 |

## 设计边界（不修复）

| 项目 | 原因 |
|------|------|
| 自愈系统不检测静默逻辑 bug | `handleRuleError` 只捕获 `throw` 异常；NaN 传播、undefined 属性、API fallback 均不抛错。属于异常监控 vs 行为监控的设计边界 |

## 后续建议

1. 在引擎中加入规则数量上限（建议 ≤ 20），超出时拒绝加载并告警
2. 在阶段四中增加规则健康度检查——如果某规则连续 N 次 check() 返回 false 但从未触发，标记为「无效规则」并建议归档
3. 考虑在 `check()` 返回后增加输出合理性校验（如价格为 NaN 或 0 时打 WARN 日志）

# [2026-05-19] 警报器引擎热重载死循环修复

## 背景

同日早些时候为规则文件新增了 `lastCheckedAt` 运行时字段，引擎每次 `check()` 后写入该字段到规则 `.js` 文件。但引擎的 `scanRuleFiles()` 扫描器通过比较文件 mtime 检测外部修改并触发热重载——引擎自己写入导致 mtime 变化，被扫描器误判为「外部修改」，形成写入→重载→写入的死循环。

## 症状

- 警报器日志中反复出现「检测到规则文件已修改」
- 引擎不断热重载规则，每次重载后又立即触发一次 `check()`
- 造成不必要的磁盘 I/O 和 CPU 消耗

## 根因分析

架构缺陷：规则文件同时承担「代码定义」和「运行时状态」两个职责。引擎的自写入被扫描器误判为外部变更。

```
runRule() → updateLastChecked(filename)
  → fs.writeFileSync() 改写规则 .js 文件  // mtime 改变
    → scanRuleFiles() 检测到 mtime 差异
      → reloadRule() → runRule()          // 再次写入
        → ... 死循环
```

## 修复内容

### 架构改动

| 文件 | 改动 | 原因 |
|------|------|------|
| `skills/btc-alert/engine.js` | 新增 `rules-state.json` 运行时状态文件，`ruleState` 内存对象及 `loadRuleState()` / `saveRuleState()` 函数 | 将运行时状态与规则定义分离 |
| `skills/btc-alert/engine.js` | `updateLastChecked()` 改为写入 `rules-state.json`，不再修改规则 `.js` 文件 | 消除自写入导致的 mtime 变化 |
| `skills/btc-alert/engine.js` | `unloadRule()` 中新增 `delete ruleState[filename]` + `saveRuleState()` | 规则卸载时清理残留状态 |
| `skills/btc-alert/engine.js` | `main()` 启动时调用 `loadRuleState()` 恢复状态 | 引擎重启后 `lastCheckedAt` 不丢失 |
| `tasks/set-alert.md` | C19 元数据字段从 11 调整为 10，模板中移除 `lastCheckedAt` 字段 | 防止新规则继续生成该字段 |

### 效果

- 规则文件 mtime 仅在真正外部修改时变化，热重载能力完整保留
- 引擎重启后 `lastCheckedAt` 从 JSON 文件恢复
- 已部署的旧规则文件中残留的 `lastCheckedAt` 字段无影响（死代码）

## 运维操作

| 操作 | 执行内容 |
|------|---------|
| 重启警报器 | `pm2 restart btc-alert`（JSON 状态文件在下次 `check()` 时自动创建） |

## 已知遗留

| 项目 | 状态 | 说明 |
|------|------|------|
| 已有规则文件中的 `lastCheckedAt` 字段 | 保留不动 | 不再被引擎写入，成为死代码，不影响运行 |

## 设计边界（不修复）

| 项目 | 原因 |
|------|------|
| 不迁移已有规则文件 | `rules-state.json` 在每轮 check 后自然充盈，无需额外迁移 |

# [2026-05-23] 阶段一历史报告搜索修复、警报名称缺失修复、OI pct 语义断层修复、健康检查持仓误覆写修复、Scanner 重试机制

## 背景
排查 NEAR 和 INJ 周期的异常现象时，发现四个独立 bug 和一个系统性缺陷，全部为框架级代码问题。

## 症状
1. 所有山寨币阶段一「历史报告收集」始终返回 0 篇，即使当前周期已有 3-7 篇报告
2. 警报引擎触发后日志显示 `警报: unknown`，无法识别触发来源
3. NEAR OI 监控规则每 4.5 分钟触发一次，阶段四不断重建同名规则，40 分钟内循环 7 轮（07:33→08:14）
4. 03:00 健康检查将 INJ 持仓快照错误覆写为空仓，实盘仍有 45 张 long + 活跃 OCO
5. Scanner 09:00 因 OKX API 返回空响应而直接终止，整小时无新币扫描

## 根因分析

### Bug 1：历史报告搜索始终返回 0
| 文件 | 根因 |
|------|------|
| `scripts/stage1-prep.js` 第5步 | `d !== cycleDir` 排除了当前周期，`active/` 下同一币种只有一个周期目录 → 永远空数组 |
| `scripts/stage1-instant.js` 第5步 | 同上 |

旧代码意图是「搜其他周期」，但 `active/` 下同币种永远只有 1 个目录。

**修复**：直接搜当前周期 `reports/` 下已有报告（阶段一执行时本篇报告尚未生成，无需排除逻辑）。

### Bug 2：alertName 缺失
| 文件 | 根因 |
|------|------|
| `scripts/stage4-executor.js` | 所有 5 种规则类型 + 1 个 fallback 的 `collectLogic` 模板中，return 对象均缺少 `alertName` 字段 |
| `skills/btc-alert/rules/NEAR-oi-monitor.js` | 同上 — 模板缺陷传播到已生成规则 |

`stage1-instant.js` 取值 `alertData.alertName \|\| 'unknown'`，因所有模板都缺字段，永远落到 unknown。

**修复**：6 个模板全部加 `alertName: \`\${this.name}\``，NEAR 规则直接补字段。

### Bug 3：OI pct 模式语义断层（核心反馈环）
| 层级 | 根因 |
|------|------|
| LLM 意图 | "OI 已涨 62%，如果再涨 25% 说明新资金涌入" → **增量阈值**（从创建时的 OI 再涨 N%） |
| 脚本实现 | `changePct = oiData.change24h`（24h 累计变化），`triggered = changePct >= 25` → **累计阈值** |
| 断层 | 当前 24h 变化为 +62%，62 ≥ 25 永远为 true → 规则一创建就触发 |
| 反馈环 | 触发 → 引擎归档 → 阶段四重建 → 新规则 `lastTriggered=0` → 冷却失效 → 再次触发 |

实证：9 次连续会话中，8 次设 pct 阈值（15-25%），全部因当前 62% 的累计变化立即触发。仅第 8 次用 absolute 模式（56M > 当前 43.7M）未触发。

**修复**：pct 模式改为首次检查记录 `baseOI`，后续判断 `(当前OI - 基准OI) / 基准OI >= threshold`，消除与 LLM 增量的语义断层。

**单元测试验证**：旧逻辑 5/5 次全部错误触发，新逻辑 2/5 次正确触发（仅真增量超阈值时触发）。

### Bug 4：健康检查持仓误覆写
| 细节 | 根因 |
|------|------|
| 03:00 查 OKX API | 返回空（可能代理/API 瞬时异常） |
| 处理逻辑 | 无重试 → 直接判定「实盘已平仓」→ 覆写 positions.json |
| 08:01 核实 | 实盘 45 张 long + OCO TP/SL 均正常 |

**修复**：
- 步骤 4.1：加 3 次重试 + 间隔退避
- 步骤 4.2：三类结果明确处理 — `found: true`/`found: false`/`found: null`
- 步骤 4.3：`found: null` → **禁止覆写**，记录 WARN
- 安全约束：加入 INJ 案例引用，API 异常时信任快照

### 改进 5：Scanner 重试机制
| 文件 | 问题 |
|------|------|
| `scripts/scanner-full.py` | OKX tickers API 调用失败 → 直接 `sys.exit(1)` 终止 |

**修复**：最多 3 次重试，间隔 2s→4s→8s 指数退避，全失败才退出。

## 影响范围
| 修复 | 影响面 | 生效时机 |
|------|--------|---------|
| 历史报告搜索 | 所有山寨币阶段一 | 即时（脚本热替换） |
| alertName | 所有后续新生成规则 | 下次阶段四运行 |
| OI pct 基准 | 所有后续新生成 OI pct 规则 | 下次阶段四运行 |

## 待自然替换
19 条活跃 OI 规则仍使用旧 `change24h` 逻辑（由修复前的阶段四生成），将在各自周期的后续阶段四运行中自然替换为新 `baseOI` 逻辑。

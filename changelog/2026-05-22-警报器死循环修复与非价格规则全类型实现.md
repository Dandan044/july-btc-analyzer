# [2026-05-22] 警报器死循环修复、非价格规则全类型实现、阶段二提示词重构

## 背景
KAITO OI 警报触发后进入无限循环（触发→崩溃→未归档→再触发），SAPIEN 周期因 LLM 判定「庄家控盘不可交易」而归档全部规则。排查发现根因涉及：阶段四代码生成模板注入、引擎 error handling 缺陷、非价格规则四类型存根、阶段二提示词缺少交易铁律。

## 症状
1. KAITO-oi-monitor.js 每 300 秒触发一次，TRIGGERED 日志反复出现但 TRIGGER_COMPLETED 永远不可达，规则无法自动归档
2. 引擎日志显示 `[❌数据收集错误] current_oi is not defined`
3. SAPIEN 周期被阶段二判定「不可交易」，阶段四将所有规则归档（SAPIEN-price-levels.js + SAPIEN-oi-monitor.js），周期无任何活跃规则
4. KAITO 四篇连续报告中，每次设置的 OI 阈值（20%/12%/12%/15%）均低于实际 OI 变化（23.43%），规则一出生就触发

## 根因分析

### A. KAITO 死循环
| 层级 | 根因 |
|------|------|
| LLM 输出 | `significance_template` 含 `${current_oi}`，意图显示绝对 OI 值，但 `${}` 语法被当作 JS 变量引用 |
| 阶段四模板 | `significance: \`${significanceTemplate}\`` 不转义 `${`，LLM 输出直接注入生成的 JS 模板字面量 |
| 生成代码 | `collect()` 中 `${current_oi}` 是未定义变量 → ReferenceError → 崩溃 |
| 引擎缺陷 | `check()`=true → `log TRIGGERED` → `collect()` 崩溃 → `archiveRule()` 不可达 → 规则留活 → 循环 |
| 引擎缺陷 | 冷却在 `trigger()` 中设置，`collect()` 崩溃导致冷却从不生效 |
| 文件再生 | 每次即时分析 → 阶段四生成同名新文件 → 引擎当新规则热加载 → `lastTriggered` 归零 |

### B. SAPIEN 规则全归档
| 层级 | 根因 |
|------|------|
| 旧报告影响力 | 5/16 归档报告含「庄家牌桌」「跑路风险 100%」措辞，LLM 读到后继承负面基调 |
| 提示词偏见 | 阶段二反复提「庄家行为疑点」「庄家资金驱动」，无反向指引 |
| 单一指标放大 | LLM 执着于 Top10=90.88%，忽略 onchainOS Risk Level 1 + Low 集群集中度 |
| 缺少交易铁律 | 无任何提示词要求 LLM 在任何市场条件下都必须找出交易机会 |

### C. 阈值设置问题
- KAITO 实际 OI 变化 23.43%，四个阈值（20/12/12/15）全部低于实际值
- 阶段二 LLM 在 `raw_data.oiData` 中能看到当前值，但未做「当前值 ≥ 阈值」检查

### Bug 修复
| 文件 | 问题 | 修复 |
|------|------|------|
| `scripts/stage4-executor.js` | `significanceTemplate` 含 `${...}` 时注入生成代码 | 新增转义函数：`$`→`\$`、`` ` ``→`` \` ``、`\`→`\\`，嵌入前全部转义 |

### significance_template 占位符汇总
| 占位符 | 适用类型 | 替换为 |
|--------|---------|--------|
| `{change_pct}` | oi-monitor | 24h OI 变化%（2位小数） |

| 项目 | 原因 |
|------|------|
| `direction: 'both'` 映射为 `above` | OI 绝对值模式已覆盖双向监控需求（`direction: 'absolute'`），`both` 仅用于旧版兼容 |

| `sigStr` 死代码 | 已在此次修复中移除 |

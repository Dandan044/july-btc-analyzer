# [2026-05-17] 讯飞错误绕过重试直接触发模型切换

## 背景

5 月 15 日的补丁（`2026-05-15-xunfei-error-classification-fallback.md`）将讯飞 6 种特有错误加入了错误分类层，使其能被 `classifyFailoverSignal` 正确归类。但实际运行发现：错误虽然被认出来了，却从未触发模型切换。

排查发现根本原因不在分类层，而在决策层：`resolveRunFailoverDecision` 在 assistant 阶段**总是先尝试 `rotate_profile`（换 API Key 重试同一模型）**，只有换 Key 失败后才进入 `fallback_model`。而讯飞只有单一 Key，「换 Key」实际不换，导致陷入重试循环。

## 症状

- `NotEnoughCvError`（及所有讯飞特有错误）出现后，系统反复重试同一模型
- 日志中「模型切换」事件为零（自 5/15 以来仅 2 次 timeout 触发的切换）
- 重试过程中若某次请求碰巧成功，错误被消化，永远不切模型

## 根因分析

决策函数 `resolveRunFailoverDecision` 在 assistant/prompt 阶段的流程：

```
failoverFailure=true, failoverReason="billing"
  → shouldRotateAssistant → true
  → profileRotated=false → action: "rotate_profile"
  → advanceAuthProfile() 假成功（单 Key）
  → retry 同一模型
  → 再次失败 → 循环
  → 直到重试上限 → 才 fallback_model
```

问题不在分类，而在决策层的**优先级**：换 Key 重试排在切模型前面，且没有针对无法重试的错误类型做短路。

| 项目 | 原因 |
|------|------|
| 不修改 `resolveRunFailoverDecision` 函数签名 | 通过 `profileRotated: true` 绕过旋转逻辑，改动最小、风险最低 |

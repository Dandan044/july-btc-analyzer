# 2026-06-01 — 分析质量三道防线

## 背景

发现系统性认知偏差问题：模型在已有方向偏好后，用乐观解读迎合偏好 → 标准不够就自己降 → 入场即浮亏。DYDX 是典型案例（开在 $0.1969 顶点，-58.8% 浮亏）。同一天 BTC 偏弱环境下系统批量开多，10/12 浮亏仓位均为做多。

根因分为两个层面：
- **分析层**：单币种分析中的认知偏差（乐观解读、选择性引用）
- **组合层**：BTC 弱时系统性批量做多（全局敞口失控，暂未修复）

本次改动部署分析层防御。

---

## 改动清单

### 一、温度参数（抑制叙事生成）

**文件**：`~/.openclaw/openclaw.json`

三个模型的 `params.temperature` 设为 0.3：
- `deepseek/deepseek-v4-flash`
- `deepseek/deepseek-v4-pro`
- `astroncodingplan/astron-code-latest`（七月默认）

### 二、双向质证协议（Stage 2 分析层）

**文件**：`tasks/pipeline/profiles/analysis-alt.md`

新增「双向质证前置协议」，在报告结构之前插入三个前置步骤：

- **前置 A：信号枚举** — 利多/利空两表，强制非空，禁止在枚举阶段写方向判断
- **前置 B：多义信号交叉解读** — 多空解读条数必须对等
- **决策追溯要求** — 开仓/观望必须引用前置 A 的信号编号

三维叙事和开仓策略中增加对前置 A 的引用要求。

### 三、监督者机制（Stage 3 执行前审查）

#### 新增文件

| 文件 | 用途 |
|------|------|
| `data/supervisor-config.json` | 动态可控参数：monitoredActions ± lazyTrigger |
| `tasks/supervisor-blind.md` | 独立市场评估（盲测阶段） |
| `tasks/supervisor-review.md` | 完整审查（交叉对比+规则评估） |

#### 修改文件

| 文件 | 改动 |
|------|------|
| `scripts/stage3-executor.js` | 新增 `--supervisor` 和 `--lazy-check` 参数。开仓/加仓操作不直接执行，改派监督者 |
| `profiles/vars-alt.json` | 新增 `supervisor_enabled: true` |
| `profiles/vars-zhuang.json` | 新增 `supervisor_enabled: false` |
| `modules/07-阶段交接.md` | `{{#supervisor_enabled}}` / `{{#zhuang_stage}}` 互斥路由 |

#### 架构

```
Stage 2 生成 trade-decision
        │
        ▼
Stage 3 --supervisor → dispatch (high-2)
        │
        ▼
监督者会话（独立模型，temperature 0.3）
  ① 盲测：独立获取 OKX 数据 → 形成独立判断
  ② 审查：读全部报告+决策文件 → 交叉对比+规则评估
  ③ 判定：PASS（执行）/ BLOCK（延迟重审）/ ARCHIVE（归档）
```

#### 触发条件

- **开仓/加仓**：monitoredActions 控制（`supervisor-config.json`，默认 open=true, add=true, reduce=false）
- **惰性触发**：无持仓 + 周期 >24h + ≥5 篇报告仍不开仓

### 四、OCO 覆盖检查修复

**文件**：`scripts/sync-alt-positions.js`

修复只取 `matchingOco[0]` 导致多档拆分 OCO（如 907+906=1813 张）被误报为覆盖不全的问题。

### 五、提示词设计哲学

`tasks/supervisor-blind.md` 和 `tasks/supervisor-review.md` 遵循 `.openclaw/PROMPT_DESIGN_PHILOSOPHY.md`：
- 给维度不给规则，给问题不给答案
- 不预设固化框架，不具体举例
- 让模型自主探索有价值的路径

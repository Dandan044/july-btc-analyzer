# [2026-05-21] Dashboard 近6h警报缓存机制

## 背景
Dashboard 前端"近 6h 警报"卡片在日志归档执行后瞬间清空，显示为无触发记录。

## 症状
- 每日凌晨日志归档 cron 执行后，"近 6h 警报"卡片立即变空
- 即使6小时内有触发记录，归档后也看不到

## 根因分析
1. **日志归档删除当天之前的行**：`log-rotate.sh` 用 `grep -v "^${YESTERDAY}T"` 从 btc-alert.log 中移除昨天日志，导致日志文件只保留当天内容
2. **前端无缓存**：server.js 每次请求直接 grep 日志文件，日志被清则数据即丢
3. **grep 关键字不匹配**（附带发现）：前端 grep `警报触发`，但引擎实际输出 `TRIGGERED`，即使有触发记录也匹配不到

## 修复内容

### 架构改动
| 文件 | 改动 | 原因 |
|------|------|------|
| `dashboard/server.js` | 近6h警报逻辑重写：日志 grep + 持久缓存合并 | 日志归档后数据丢失 |
| `data/recent-alerts-cache.json`（新增） | 缓存文件，存储6小时内的触发记录 | 跨日志归档周期保留数据 |

### Bug 修复
| 文件 | 问题 | 修复 |
|------|------|------|
| `dashboard/server.js` | grep 关键字 `警报触发` 与引擎输出 `TRIGGERED` 不匹配 | 改为 grep `TRIGGERED`，正则提取规则名 |

## 缓存设计
- 缓存文件：`data/recent-alerts-cache.json`
- 结构：`{ alerts: [{ id, time, rule, ts, cachedAt }] }`
- 去重 ID：`时间戳::规则名`（同一事件不重复录入）
- 清理策略：每次 API 请求时过滤掉6小时外的记录
- 合并流程：日志新记录 + 缓存旧记录 → 去重 → 清理过期 → 写回缓存

# [2026-05-21~22] 山寨币流程 LLM 减负

## 背景

山寨币分析流程的每个阶段都完全由 LLM 执行，大量步骤是纯机械操作（API 调用、文件系统操作、JSON 拼装）。每小时扫描触发一次完整四阶段，token 消耗巨大。目标是将所有确定性逻辑脚本化，LLM 只做不可脚本化的推理工作。

---

## 改造进度总览

| 环节 | 原状态 | 改造后 | LLM token 节省 |
|------|--------|--------|---------------|
| 扫描引擎 | LLM 执行 10 步 | ✅ `scanner-full.py` 纯脚本 | 100% |
| 阶段一（正式） | LLM 执行 8/10 步 | ✅ LLM 仅做 sentiment（2 步） | ~70% |
| 阶段一（即时） | LLM 执行 8 步 | ✅ `stage1-instant.js` 100% 脚本 | 100% |
| 阶段二 | 全部 LLM | ✅ 新增 `trade-decision.json` 结构化输出 | 减少阶段三 token |
| 阶段三 | 全部 LLM | ✅ `stage3-executor.js` 零 LLM | 100% |
| 阶段四 | 全部 LLM | 未改造 | — |

> **关键成果：阶段三从「LLM 读报告→理解意图→执行交易」变为「读 JSON→脚本执行」，消除一次完整 agentTurn。**

## 改造详情

### 阶段二：输出结构化开仓数据

阶段二 LLM 写完报告后，同时输出 `trade-decision-{COIN}.json`：

```json
{
  "coin": "SOL",
  "report_file": "alt-report-SOL-2026-05-22-0000.md",
  "action": "open",           // open | add | reduce | close | adjust | hold
  "direction": "long",        // long | short
  "entry_condition": "immediate",
  "nominal_base": 40,         // 建议名义仓位（USDT）
  "calc_position_input": {"entry": 86.28, "x": 1.5, "levels": [...]},
  "stop_loss": 81.97,
  "take_profit1": 94.91,
  "take_profit2": 103.54,
  "tp1_ratio": 50,
  "reject_reason": null,      // 非 null 时阶段三跳过
  "reduce_ratio": null,       // 减仓比例，仅 action=reduce
  "observation_conditions": []
}
```

阶段二末尾执行 `node scripts/stage3-executor.js {COIN} {CYCLE_DIR}`，不再路由到阶段三 md。

### 阶段三：零 LLM 仓位执行

`stage3-executor.js` 支持 5 种操作 + 归档：

| 操作 | 日志标识 | 核心逻辑 |
|------|---------|---------|
| 开仓 | `💰 OPEN` | 余额→合约信息→张数计算→市价单→OCO |
| 加仓 | `💰 ADD` | 市价单→合并 OCO 更新 |
| 减仓 | `💰 REDUCE` | 反向市价单（按比例）→更新 OCO |
| 平仓 | `💰 CLOSE` | 取消 OCO→反向市价全平 |
| 调整 | `💰 ADJUST` | 取消旧 OCO→偏移计算→新 OCO |
| 归档 | `📦 ARCHIVE` | 持仓=0+最近平仓≠null → archive-cycle.js |

**风控机制：**
- BTC 逆势对冲（y=0.5，对冲后 <20u 则跳过）
- 止盈止损偏移（TP 收紧 5%、SL 放宽 5%）
- 方向冲突检测（有仓时反方向开仓→跳过）
- 操作后自动调用 `sync-alt-positions.js` 同步

**输出：** JSON 到 stdout（最后一行 `__STAGE3_OUTPUT__`），日志到 `logs/alt-{COIN}-process.log`。

## 修复的 Bug（测试中暴露）

| # | 问题 | 影响 | 修复 |
|---|------|------|------|
| 1 | 顶层 await 不兼容 CommonJS | 脚本无法启动 | async IIFE 包裹 |
| 2 | `runOkxCmd` 多行 JSON 解析失败 | 所有 OKX 命令返回 null | 从输出中找 `[`/`{` 位置切片 |
| 3 | 余额 API `availBal` 路径错误 | 余额检查失败 | `details[0].availBal` |
| 4 | `--slOrdPx -1` 被 CLI 当成选项 | OCO 下单失败 | `--slOrdPx=-1` |
| 5 | OCO 下单缺少 `--side` 参数 | OCO 下单失败 | 动态 `long→sell / short→buy` |
| 6 | `swap orders` 命令不存在 | CLOSE 中 ERROR | 移除无用检查 |
| 7 | trade-decision 文件字母序排序 | 选中旧文件而非最新 | 改用 `fs.statSync.mtimeMs` |
| 8 | adjust 缺少无仓位检查 | 无仓时 adjust 崩溃 | 添加 hasPosition 检查 |

## 时区修复（影响 7 个脚本）

| 脚本 | 问题 |
|------|------|
| `stage3-executor.js` | `nowTs()` 用 UTC |
| `sync-alt-positions.js` | log 时间 UTC + `syncTime` 值错误 |
| `stage1-prep.js` | `nowTs()` + `dateStr` + `bl.updated` UTC |
| `stage1-instant.js` | `nowTs()` + `dateStr` UTC |
| `gen-stage1-manifest.js` | `dateStr` UTC |
| `sync-positions-temp.js` | `syncTime` UTC |

全部改为 `new Date(Date.now() + 8 * 3600000)` → GMT+8。

## 日志前缀修复

`sync-alt-positions.js` 被阶段三调用时输出 `[阶段一]` 前缀，与阶段三日志混杂。改为 `[同步]`。

## 新流程

```
Linux cron (0 * * * *)
  │
  ▼
bash scanner-runner.sh
  ├── python3 scanner-full.py          → 扫描命中 COIN
  ├── node stage1-prep.js COIN         → 预处理（失败→退出）
  └── openclaw cron add (1min)
        │
        ▼
    agentTurn: LLM
        ├── 读 alt-pipeline/alt-intel-stage1-v2.md → sentiment 收集
        ├── node gen-stage1-manifest.js             → 数据清单
        ├── 读 alt-pipeline/alt-intel-stage2.md     → 交叉验证 + 报告 + trade-decision.json
        ├── node stage3-executor.js COIN CYCLE_DIR  → 仓位执行（纯脚本）
        └── 读 alt-pipeline/alt-intel-stage4.md     → 警报管理
```

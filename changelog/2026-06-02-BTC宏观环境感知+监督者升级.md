# 2026-06-02 — BTC 宏观环境感知 + 监督者机制升级

## 背景

四个持仓中三个做多、全部浮亏。根因分析发现：山寨币分析流程缺少 BTC 宏观环境维度——技术面上币种自身信号良好，但 BTC 下行趋势成为压倒性因素。对冲系数（y）只能减小仓位、不能阻止开仓。

同时监督者机制存在两个缺陷：(1) 盲测阶段被透露了操作方向，不是真正的盲测；(2) 审查缺乏对抗性思维，容易被分析师的自洽叙事说服。

---

## 改动清单

### 一、BTC 跟踪度计算重构

**文件**：`scripts/calc-btc-correlation.js`（重写）

从单一 1H Pearson → 多时间框架（1H/4H/1D）+ Beta 系数 + 下行半相关。

```json
{
  "timeframes": {
    "1H(3天)": { "correlation": 0.194, "beta": 0.978, "downside_corr": 0.031 },
    "4H(3天)": { "correlation": -0.248, "beta": -0.959, "downside_corr": -0.221 },
    "1D(7天)": { "correlation": 0.301, "beta": 1.796, "downside_corr": null }
  }
}
```

三个指标互补：Pearson 测方向一致性、Beta 测幅度放大系数、下行半相关测 BTC 跌时真跟踪度。多框架揭示短期噪音 vs 结构性关系。

### 二、阶段一自动采集 BTC 跟踪度

**文件**：`scripts/stage1-prep.js`（新增步骤 9）、`scripts/stage1-instant.js`（新增步骤 5.5）

两条入口（扫描触发 + 警报触发）均自动运行 `calc-btc-correlation.js`，输出到 `active/{CYCLE}/data-context/btc-tracking.json`。

### 三、BTC 走势展望定时任务

**新增文件**：`tasks/btc-outlook.md`

每 4 小时独立运行，产出 BTC 4H/24H 走势展望 JSON（五档评分：strong_bullish → strong_bearish + 关键价位 + 理由），保存到 `data/btc-outlook.json`。使用与日报相同的数据源。

Cron：`0 0,4,8,12,16,20 * * * Asia/Shanghai`

### 四、阶段二 BTC 环境维度（仅 alt）

**文件**：`tasks/pipeline/profiles/analysis-alt.md`

新增三个接入点：
- **步骤 X**：分析前读取 `btc-outlook.json` + `btc-tracking.json`
- **BTC 市场环境**（在三、市场判断中）：四个追问——顺风逆风 / 跟踪度结构特征 / 耐心等待 / 止损重估
- **决策原则**：BTC 4H 逆风但 24H 顺风 + 脱钩 → 等待更好入场价；双逆风 + 无脱钩 → 观望

### 五、监督者机制升级

**文件**：`tasks/supervisor-blind.md`、`tasks/supervisor-review.md`、`scripts/stage3-executor.js`

| 改动 | 说明 |
|------|------|
| 真盲测 | 不再透露操作方向/类型，写入 `supervisor-intent.json`，审查阶段才揭晓 |
| 对抗心态 | 「你不是来点头的，是对方辩护律师」——追问反向叙事、逻辑脆弱点、时间验证 |
| 耐心分级 | 无疑点→PASS / 轻微疑点→DELAY 15m / 实质性可疑→BLOCK(30m/1h/2h) / 方向错误→ARCHIVE |
| 审查报告 | 强制产出 `supervisor-review-*.md`，保存到周期 reports 目录 |
| BTC 数据 | 盲测阶段可读 `btc-outlook.json` + `btc-tracking.json`，与分析师同一宏观框架 |

### 六、Dashboard 审查记录视图

**文件**：`dashboard/server.js`（新增 `/api/supervisor-reviews`）、`dashboard/public/index.html`

开仓决策卡片头新增「🔍 审查记录」切换按钮，可查看所有审查报告列表（时间/币种/判决），点击展开完整报告内容。

### 七、OCO 拆分覆盖率修复

**文件**：`scripts/stage3-executor.js`

4 个拆分路径（OPEN/ADD/REDUCE/ADJUST）：szTp2 从 `alignToLot(remaining)` 改为 `round(sz - szTp1, 8)`，确保最后一个桶自动吸收 lotSz 对齐余量，OCO 覆盖始终 100%。

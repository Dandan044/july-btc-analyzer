# 2026-06-07 — 阶段三脚本：全仓→逐仓改造 + 动态杠杆 + 实时 MMR

## 背景

阶段三脚本（`stage3-executor.js`）此前固定使用全仓模式，无法精确控制爆仓价。本次改造目标：
- 从全仓切换到逐仓模式，精确控制爆仓价 = 止损价 × 1.10
- 爆仓价如无法精确对齐则至少不近于 SL×1.10（偏安全侧）

## 改造内容

### 1. 保证金模式：cross → isolated

- 所有杠杆设置命令加上 `--posSide` 参数（逐仓模式要求）
- 下单命令 `--tdMode isolated`
- 安装 OKX REST API 签名调用模块（`crypto` + `okxRestPost`），用于 CLI 不支持的保证金追加操作

### 2. 动态杠杆：根据 SL 反算

新增 `calcIsolatedLeverage(entry, SL, direction, minLever, maxLever, mmr)`：

```
杠杆 = 入场价 / (|入场-SL| × 1.10 + MMR × 入场价)
钳制到 [面板杠杆下限, 合约上限]，向下取整
```

| 路径 | 杠杆来源 | 备注 |
|------|---------|------|
| 市价开仓 | 动态计算 | SL 必传（硬性要求） |
| 加仓 | 动态计算 | 基于加权均价 + SL |
| 限价单 | 动态计算 | SL/TP 硬性要求，否则拒绝 |
| 条件单 | 面板设置（默认 10x） | 无 SL 可推算 |

### 3. 实时 MMR：替代硬编码 1%

新增 `fetchContractMmr(instId, sz, ctVal, price)`：
- 调用 OKX 仓位档位 API `/api/v5/public/position-tiers`
- 按合约实际张数匹配档位，返回真实 MMR
- 带缓存（同合约不重复请求）
- 回退值 7%（API 失败时保守兜底）

此前硬编码 MMR=1%，导致低市值币（如 RLS MMR=5%）保证金追加严重不足，强平价比止损更近。

### 4. 保证金追加

新增 `calcIsolatedMarginExtra(sz, ctVal, entry, SL, direction, leverage, mmr)`：

```
所需保证金 = sz × ctVal × (|entry - SL| × 1.10 + entry × MMR)
默认保证金 = sz × ctVal × entry / 杠杆
追加 = max(0, 所需 - 默认)
```

仅当杠杆触底（面板下限）或触顶（合约上限）、默认强平距不足时才追加。通过 OKX REST API `POST /api/v5/account/position/margin-balance` 执行。

### 5. 市价/限价开仓硬性要求止盈止损

`executeOpen` 和 `executeLimitOpen` 入口处增加检查：
- 缺少 `stopLoss` 或 `take_profit1` → `throw Error` 拒绝执行
- 删除原有的"默认 ±5% 保险"逻辑
- 限价单 TP/SL 无条件附带（不再有可选分支）

### 6. 执行顺序重构

三个开仓/加仓函数全部改为：先算张数 → 取 MMR → 算杠杆 → 设杠杆。MMR 依赖张数（确定档位），张数不依赖杠杆。

### 7. sync-alt-positions.js 同步改造

- 移除 `--tdMode` 过滤，同时查询 cross + isolated 模式仓位
- `mgnMode` 字段从硬编码 `'isolated'` 改为动态读取

## 测试验证

| 测试项 | 币种 | 结果 |
|--------|------|------|
| 逐仓开仓 | SOL | 15x 杠杆, 强平距 5.99% ≈ SL×1.10=5.60% ✅ |
| 加仓 | SOL | 15x, OCO 正确替换, 50/50 拆分 ✅ |
| 低市值 MMR | RLS | MMR=5.0% 正确获取, 追加保证金 0.14u, 强平 7.42% > SL×1.10=6.93% ✅ |
| MMR 缓存 | RLS | 二次加仓复用缓存, 无额外 API 调用 ✅ |

## 副作用

- 全仓→逐仓后，旧的全仓仓位对 sync 脚本不可见（已在本次改造中修复）
- 脚本非幂等：如果在"下单成功但 OCO 未设"时超时被杀，重跑会再加仓
- MMR API 调用增加 ~5s 耗时（缓存后首次调用），已通过 `fetchContractMmr` 缓存和缩短超时缓解

# 2026-05-23 — 阶段三阻拦逻辑移除 + 加仓/减仓 OCO 管理修复

## 变更背景

Dandan 要求阶段三只做一件事：**阶段二决定什么就执行什么，不替模型做任何预设判断**。同时修复了加仓和减仓操作中的 OCO 算法单管理缺陷。

---

## 变更详情

### 1. 移除全部预设阻拦逻辑（4处）

| 位置 | 原逻辑 | 移除原因 |
|------|--------|---------|
| 步骤 5 方向冲突 | `hasPosition && action === 'open' && direction !== positionDirection` → skip | 阶段二知道当前持仓，反方向开仓有它的理由 |
| 步骤 6.X 20u下限 | `nominalFinal < 20` → skip | 阶段二决定了名义值，脚本不设下限 |
| `executeOpen()` 余额不足 | `available < 5 USDT` → return | 余额不足让 OKX 报错，脚本不预判 |
| `executeAdd()` 余额不足 | `available < 5 USDT` → return | 同上 |

**保留的 skipExecution：**
- `reject_reason`（阶段二决策输入）
- `hold` / `观望`（阶段二决策输入）
- `entry_condition !== 'immediate'`（阶段二策略输入）
- 无仓位但 `reduce/close`（逻辑不可能）

### 2. 加仓 `executeAdd()` 修复

**原来的问题：**
- 没取消旧 OCO → 新旧算法单共存，管理合约量 > 实际总仓位
- 新 OCO 的 `sz` = 本次加仓量，不是总仓位
- `entryPx = lastPrice`，和原始入场价不同 → TP/SL 价格偏移不同

**新逻辑：**
1. 保存旧 OCO 价格（`extractOcoPrices()`，新增函数）
2. 取消旧算法单
3. 执行加仓市价单
4. 查询最终持仓（总张数 + 加权均价）
5. 用**加权均价**计算偏移，按**总仓位**设新 OCO

### 3. 减仓 `executeReduce()` 修复

**原来的问题：**
- 没取消旧 OCO → 旧单管 `currentSz` 张 + 新单管 `remainingSz` 张 = 超额
- `entryPx = lastPrice`，和入场均价不同

**新逻辑：**
1. 保存旧 OCO 价格
2. 取消旧算法单
3. 执行减仓市价单
4. 查询剩余仓位（API 实际确认）
5. 用**原始入场均价**计算偏移，按**剩余仓位**设新 OCO

### 5. 双模式 TP/SL 选择

| 模式 | 条件 | 行为 |
|------|------|------|
| A: 阶段二传参 | `stopLoss && tp1` | 用传入参数通过 `calcPnlOffset` 计算偏移 |
| B: 兜底复用 | 阶段二未传 && 旧 OCO 有价 | 直接复用旧 OCO 价格（已是偏移后，不二次偏移） |
| 超出 | 两者都无 | 跳过止盈止损设置，打印 WARN，操作仍执行 |

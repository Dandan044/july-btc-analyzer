# 2026-06-05 — 异动检测引擎（Anomaly Detection Engine）设计启动

## 背景

通过 OPN 和 ZEC 两个案例的 15min K 线溯源，发现两种催化剂驱动模式：

| 模式 | 案例 | 特征 |
|------|------|------|
| **量能先行型** | OPN | 无消息异动 → 13.7x 量比起爆 → 4.5h 后消息追认 |
| **消息先行型** | ZEC | 漏洞→软/硬分叉 → 消息公开后 18-40h 延迟崩盘 → 8.8x 量能确认 |

现有 altcoin scanner 是技术面驱动的，无法捕获此类事件驱动的极端波动机会。

## 设计概览

### 架构

```
Anomaly Engine (PM2 daemon)
├── Volume Scanner  — 15min OKX candles, Top200 SWAP, vol/SMA20 阈值触发
│   └── PATH A: 量能先行 → 先入场 → LLM 分析 → 监控消息
├── News Scanner    — RSS/媒体/解锁日历, 关键词分级匹配
│   └── PATH B: 消息先行 → LLM 评估 → 设置量能/价格监控
└── 共享分析层       — tasks/anomaly/ 下统一分析规则
```

### 关键参数（初始值）

| 参数 | 值 | 来源 |
|------|-----|------|
| 15min 量比阈值 | 8x SMA20 | OPN 13.7x / ZEC 8.8x 的中间偏低 |
| 基线计算窗口 | 20 根 K 线 | 标准 SMA |
| 同币种冷却 | 30min | 防重复触发 |
| 最低基线量 | 100K/15min | 过滤流动性枯竭币 |

### 消息关键词分级

- **CRITICAL**: vulnerability, hack, exploit, emergency fork, delist, SEC, lawsuit
- **MAJOR**: listed, partnership, launch, acquire, integration, 上线, 合作
- **MINOR**: unlock, upgrade, proposal, vesting, AMA, 解锁

### 与现有系统关系

- altcoin scanner → 互补（技术面 vs 事件驱动）
- BTC alert engine → 独立
- position monitor → 增强（异常信号喂入复核）
- cron dispatcher → 复用

## 决策点

- 监控范围 → 待定（Top200 还是仅周期内）
- Path A 入场 → 待定（自动执行 vs 生成建议）
- 消息源 → 待定（RSS 优先 vs CryptoPanic）
- 推送通知 → 待定（实时 vs 汇总）

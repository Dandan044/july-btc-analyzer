# [2026-05-17] BTC 对冲系数与山寨 BTC 趋势对冲

## 背景

七月的交易系统存在两个结构性的仓位失衡问题：

1. **BTC 侧**：BTC 开仓独立于全账户多空仓位比例。当账户已严重偏向某一方向（如 81% 空头）时，BTC 继续同向开仓会放大失衡风险。

2. **山寨侧**：山寨币普遍偏空，但缺少 BTC 趋势考量。当 BTC 上涨时，高跟踪度的山寨币会跟涨，导致大量做空仓位同时被挤压。

本次更新在 BTC 和山寨两条开仓链路中分别植入对冲机制——BTC 对冲全账户失衡，山寨对冲 BTC 趋势逆风。

## 根因分析

### 根因 1：BTC 仓位未与全账户敞口联动

BTC 的独立分析和仓位决策完全基于 BTC 自身数据，从未考虑「账户里还有 10+ 个山寨做空仓位」这一事实。当全账户空头占比达 81% 时，BTC 做空是在加码同向风险。

### 根因 2：山寨分析缺少第四维——BTC 方向

阶段二的交叉验证分析审视了媒体面、链上数据和合约技术面，但缺少 BTC 趋势这一关键维度。山寨币的 beta 通常在 1.5-4x，BTC 的方向对山寨价格有决定性影响。

### 根因 3：山寨 BTC 跟踪度从未被量化

系统没有计算过山寨币与 BTC 的跟踪程度。本次实测发现：
- 主流币/高跟踪山寨：ETH(0.88), SOL(0.85), PENGU(0.89)
- 普通山寨：0.50-0.85 区间
- 强庄币：SAHARA(0.04), LAB(0.21)——几乎不跟 BTC

### 对冲公式

**BTC 侧**：

```
y = 0.5 + opposing_ratio

BTC做多: opposing = 全账户空头名义占比
BTC做空: opposing = 全账户多头名义占比
y ∈ [0.5, 1.5]

y < 1: 账户已偏同向，缩减仓位
y = 1: 均衡，无调整
y > 1: 账户偏反向，放大对冲
```

**山寨侧**：

```
1. 判逆势: btc=bearish ∧ alt=long → 逆势
           btc=bullish ∧ alt=short → 逆势
           其他 → 顺势 (y=1.0)

2. 若逆势:
   corr = BTC 跟踪度 (3天1H Pearson r)
   y = 1.0 - 0.5 × (corr - 0.15) / (0.85 - 0.15)
   clamp [0.5, 1.0]

   常数: CORR_MIN=0.15, CORR_MAX=0.85
```

### 异常处理

| 异常 | BTC 对冲 | 山寨对冲 |
|------|---------|---------|
| 无山寨持仓 | y=1.0（无调整） | — |
| BTC 周期不存在 | — | y=1.0（视为 sideways）+ WARN |
| BTC 报告无法读取 | — | y=1.0（视为 sideways）+ WARN |
| 跟踪度计算失败 | — | 回退 corr=0.5 → y≈0.75 |
| NOMINAL_FINAL 低于下限 | 100u 下限 | 20u 下限 → 终止开仓 |

## 设计边界（不修复）

| 项目 | 原因 |
|------|------|
| BTC 对冲不调整止盈止损 | 用户明确要求：只动仓位，不动止盈止损/盈亏比 |
| 山寨 y 不放大（上限 1.0） | 山寨仓位原本就小（20-40u），放大无意义，只做缩减 |
| 顺势时 y=1.0 | 顺势不需要对冲，阶段二独立判断即可 |
| BTC 趋势由 LLM 从报告识别 | 不使用指标规则（如 EMA 排列），因为报告已综合全部信息 |

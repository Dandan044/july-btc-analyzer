# Cron 调度器完整重构

> 日期：2026-05-26
> 范围：`scripts/cron-dispatcher.js` `dashboard/server.js` `dashboard/public/index.html` `data/cron-dispatcher-config.json` `scripts/dispatch.js` `TOOLS.md`

---

## 一、问题背景

原调度器 `pollModelLoad()` 使用同步 `execSync('openclaw cron list --json')` 采集模型负载。当 gateway 响应慢时，事件循环被阻塞长达 10 秒，HTTP 服务器 (3102) 无法响应 `/status` 请求，Dashboard 5 秒超时触发 → 前端持续显示「调度器超时」。

同时，原载荷算法使用固定 5 分钟窗口、不识别运行态、模型匹配只认 `--model` 参数，存在多处设计缺陷。

---

## 二、架构变更

### 2.1 载荷采集：同步阻塞 → 异步缓存

```
之前: pollModelLoad() → execSync(openclaw cron list) → 阻塞事件循环 4-5s
现在: refreshLoadCache() → spawn detached (每30s) → 写 data/cron-list-cache.json
      pollModelLoad() → readFileSync(缓存文件) → 8ms
```

Dashboard 的 `/api/cron/jobs` 也从 CLI 调用改为读缓存文件（4-5s → 毫秒级），加了 `/api/cron/jobs/live` 用于手动刷新按钮。

### 2.2 动态窗口载荷模型

**核心变化：** 载荷计算从固定 5min 窗口 → 基于任务执行时间的动态窗口重叠检测。

```
之前: nextRunAt in [now, now+5min] → pending（粗暴）
现在: 为每个 job 计算 [windowStart, windowEnd]，新任务窗口有交集 → 计为并发

运行态检测: state.runningAtMs 存在 → 正在执行（精确）
模型识别: --model → agent 配置 → 全局默认（三级 fallback）
```

关键函数：`computeLoad(modelId, taskAt, taskDuration)` — 窗口重叠检测。

```javascript
// 24h 后的 review 任务不会和现在的 scanner 任务抢槽位
// 只有同时间段的窗口重叠才参与竞争
```

### 2.3 模型池架构：intelligence 匹配 → 池独立模型

```
旧: { models: [{id, intelligence, max}], pools: {POOL_MAIN: {intelligence: ["high"]}} }
新: { pools: { POOL_MAIN: { models: [{id, max_concurrent, weight}] } } }
```

每个池独立拥有模型列表，不再通过 intelligence 匹配。Dashboard 设置页支持完整的池/模型 CRUD。

### 2.4 优先级路由简化

```
旧: high-3→POOL_A, high-2→POOL_B, high-1→POOL_C, ...
新: HIGH→池A, MED→池B, LOW→池C

数字后缀 (1/2/3) 只影响同层排队顺序，不影响分池。
```

## 三、Dashboard 前端重构

### 3.1 Cron 调度器卡片

- 首次渲染骨架 + 后续增量更新（不闪）
- 7 级队列条状图 → HIGH/MED/LOW 三级 + 池路由标签
- 即时载荷进度条只显示 active（正在跑），pending 仅作为提示
- 24h 热力图：48 槽 × 动态渐变色（max 取全局值），支持池选择器
- 原始调度日志：等宽字体 + 时间戳 + 高对比底色
- 30s 自动刷新，切换 tab 清除

### 3.2 Cron 任务管理卡片

- 数据源切换为缓存文件（毫秒级），手动刷新调 gateway 即时获取
- 点击行展开完整参数：模型、超时、lightContext、delivery、消息、错误
- 30s 自动刷新

### 3.3 设置页 — 模型池配置

- 池子管理：新建/删除
- 模型管理：从 43 个已注册模型中添加/移除，修改 max_concurrent
- 路由配置：HIGH/MED/LOW → 池下拉选择
- 每次修改自动备份 + 热重载调度器

### 3.4 刷新按钮动画

所有手动刷新按钮使用 `spinRefresh(btn, fn)` 工具——持续旋转直到完成。

## 四、Bug 修复

| Bug | 原因 | 修复 |
|-----|------|------|
| 调度器超时 | `execSync` 阻塞事件循环 | 改为异步 spawn + 缓存文件 |
| `openclaw cron list` 4-5s | gateway 响应慢 | Dashboard 读缓存，不调 CLI |
| 任务延后 8h | `Date.now() + 8*3600000` 时区错误 | 移除 +8h，`Date.now()` 即 UTC |
| active 计数翻倍 | 内部追踪 + cron 导入重复 | 双向去重 `internal:` + `cron:` 条目 |
| 运行中任务被过期剔除 | `lastDurationMs` 为空 fallback 10min 不足 | `windowEnd = max(runningAt+dur, now+60s)` |
| 即时载荷包含 1h 后任务 | STATUS_WINDOW 1h 过宽 | 改为 10min |

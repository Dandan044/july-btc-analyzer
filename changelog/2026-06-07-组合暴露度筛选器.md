# 2026-06-07 — 组合 BTC 暴露度计算 + 开仓硬性筛选器

## 背景

现有系统每个山寨币开仓都做了独立的 BTC 跟踪度分析（corr/Beta/下行半相关），但缺乏组合级别的风险评估。当市场趋势一致时，可能开出多个高度相关的同向仓位——名义上分散，本质上是同一个 BTC 方向性赌注的重复下注。趋势反转时所有仓位集体亏损。

需求：在现有逐币分析之上，增加一层组合维度的风险测量和硬性开仓筛选。

## 改造内容

### 1. 新建 `scripts/calc-portfolio-exposure.js`

组合暴露度计算脚本，两种模式：

```bash
# 快照模式：查看当前组合风险
node scripts/calc-portfolio-exposure.js

# 候选模式：评估开仓请求的边际影响
node scripts/calc-portfolio-exposure.js --candidate COIN --direction long|short --nominal N
```

**输出指标（6 项）：**

| 指标 | 说明 |
|------|------|
| 加权 Beta | 按 notionalUsd 加权，多单正贡献/空单负贡献 |
| abs(加权 Beta) | 组合对 BTC 方向暴露的绝对值（主指标） |
| 加权下行相关 | BTC 下跌区间组合跟跌程度 |
| 方向暴露 | long%/short%（辅助指标，权重 10%） |
| 互相关集群 | pairwise Pearson > 0.70 形成集群，含有效占比（多空混合折算） |
| 压力测试 | BTC ±3%/±5% 情景，用不对称 Beta（下行/上行分别计算） |

**不对称 Beta：** BTC 下跌场景用下行 Beta，BTC 上涨场景用上行 Beta。结束之前对称 Beta 导致压力测试两边完全镜像的失真。

### 2. 风险评分权重

| 指标 | 权重 | 理由 |
|------|------|------|
| 方向暴露%(long/short) | 10% | 降权，方向只是表象 |
| abs(加权 Beta) | 15% | 真实 BTC 暴露，负相关多单不会被误杀 |
| 集群有效占比 | 25% | 跨币种冗余度 |
| 绝对相关幅度 | 20% | 仓位间整体共动程度 |
| 压力测试(不对称) | 30% | 升权，天然含 dirSign × Beta |

### 3. 阶梯硬拒绝阈值

| 笔数 | absBeta | 集群有效 | 压力测试 |
|------|---------|---------|---------|
| 1-3 | 不放行 | 完全 | 不拦截 |
| 4 | >1.5 | >55% | >12% |
| 5 | >1.2 | >45% | >10% |
| 6+ | >1.0 | >40% | >8% |

前 3 笔不限制（冷启动问题）。不含软建议，只输出 pass/reject + 理由。

**改善豁免：** 新仓位降低组合风险评分 → 无条件通过，不受阶梯阈值约束。确保对冲仓位（即使是同向的负相关币种）不会被误杀。

### 4. 缓存策略

- K 线数据缓存：`data/cache/kline-{COIN}.json`，15 分钟 TTL
- 跟踪度缓存：`data/cache/btc-correlation-{COIN}.json`，15 分钟 TTL
- 避免重复拉 OKX API（多仓位时尤其重要）

### 5. 时间框架

当前使用 1H × 72 根（约 3 天）。已知局限：短期噪音会使互相关矩阵偏高，多币种容易被合并入同一集群。后续可考虑升级为 4H 交叉确认，但复杂度显著增加，暂不实施。

## 模拟验证

用最近 10 个平仓币种（去重后按时间正序）模拟逐个开仓：

```
1. W     空 → 通过
2. OFC   空 → 豁免（降低风险）
3. BSB   空 → 通过
4. WIF   空 → 拒绝（absBeta+集群）
5. TRUMP 空 → 拒绝（集群）
6. JELLY 空 → 豁免（降低风险）
7. JUP   空 → 拒绝（absBeta+集群）
8. FLOW  空 → 拒绝（absBeta+集群）
9. ZORA  空 → 拒绝（absBeta+集群）
10. TRIA 多 → 豁免（降低风险）
```

结果：5 通过 / 5 拒绝，第 4 笔即发现问题。最终组合 W/OFC/BSB/JELLY/TRIA 互不相关，风险可控。

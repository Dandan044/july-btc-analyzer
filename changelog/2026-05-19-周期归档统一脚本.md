# [2026-05-19] 周期归档统一脚本 — 三步骤自动化

## 背景

周期归档需要三个独立步骤：验证仓位、归档警报规则、移动目录。此前这些操作分散在阶段三（手动 `mv`）和阶段四（`archive-rules.js`）两个阶段，且盈亏数据依赖 stage3 手动写入的 `positions.json`，无实盘验证环节。

## 症状

- 归档操作割裂：目录移动在阶段三、规则清零在阶段四
- 盈亏数据无实盘交叉验证：`positions.json` 中的「最近平仓」完全依赖 stage3 手动写入
- 无统一入口：BTC 和山寨币归档流程相同但代码重复
- 枚举值硬编码：规则归档来源 `--by`、原因 `--reason`、平仓类型全部写死，无法自定义

## 根因分析

1. 无统一归档脚本 — 三个步骤各自用原始 shell 命令
2. OKX 盈亏同步尝试使用 CLI 表格输出（`okx account bills` 无 `--json`），JSON 解析失败被静默吞掉
3. 参数设计时未考虑人工覆盖场景

## 修复内容

### 架构改动

| 文件 | 改动 | 原因 |
|------|------|------|
| `scripts/archive-cycle.js` | **新文件 v2** — 统一归档 CLI（三步骤） | 单一入口，盈亏同步 + 规则归档 + 目录移动 |
| `tasks/daily-report-stage3.md` §9.2 | `mv active/xxx archived/` → `archive-cycle.js --cycle xxx` | 统一入口，附带实盘盈亏同步 |
| `tasks/alt-intel-stage3.md` §9.2 | 同上 | 同上 |
| `tasks/daily-report-stage4.md` 分支A | 新增说明：规则可能已被 stage3 的 archive-cycle.js 归档，A.1-A.3 应检测跳过 | 避免重复归档 |
| `tasks/alt-intel-stage4.md` 分支A | 同上 | 同上 |
| `TOOLS.md` | 新增 `archive-cycle.js` 条目（含完整参数说明） | 工具笔记 |

### 盈亏同步修复

| 项目 | v1（已废弃） | v2 |
|------|-------------|-----|
| 数据源 | `okx account bills` 表格输出 | `okx --json --env account positions-history` |
| JSON 解析 | `JSON.parse()` 表格 → 静默失败 | `JSON.parse()` 结构化 JSON → 正确解析 |
| 盈亏字段 | 无 | `openAvgPx` / `closeAvgPx` / `pnl` / `realizedPnl` / `fee` / `fundingFee` |
| 平仓类型推断 | 无 | OCO 订单 → TP/SL 方向推断，无信息 → 「手动平仓」 |
| 默认行为 | 尝试同步但实际空操作 | 默认同步实盘盈亏（`--no-sync` 跳过） |

### 枚举参数补全

| 参数 | 默认值 | 枚举/类型 |
|------|--------|----------|
| `--by` | `cycle-archived` | `stage4-cleanup` / `trigger-fired` / `cycle-archived` / `cycle-health-check` / `manual` / `lifetime-expired` |
| `--reason` | `"{币种}周期归档，警报清零"` | 任意文本 |
| `--close-type` | 自动推断 | `止损触发` / `止盈触发` / `手动平仓` / `部分止盈` / `追踪止损` / `强制平仓` / `手动归档` / `价格监控专用` |

参数传递链路：`archive-cycle.js` → `--by` + `--reason` → `archive-rules.js`（写入规则 `archivedBy` / `archiveReason`），`--close-type` → 覆盖 `positions.json` 平仓类型。

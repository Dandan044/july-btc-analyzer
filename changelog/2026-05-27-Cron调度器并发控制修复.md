# Cron 调度器并发控制修复

**日期**: 2026-05-27 00:00
**严重度**: 高 — 导致 6 个任务同时涌入 max_concurrent=3 的池子
**影响范围**: 所有 high 优先级任务（instant 类型为主）

---

## 事故现象

23:46:12，6 个 high-1 任务同时 DISPATCH 到 deepseek 池（max_concurrent=3），全部 `cron add` 返回 exit=1，其中 5 个实际被创建到 cron（1 个 COMP 真正失败）。

```
23:46:12 [DISPATCH] high-1 | COMP | model=deepseek/deepseek-v4-flash
23:46:12 [DISPATCH] high-1 | CORE | model=deepseek/deepseek-v4-flash
23:46:12 [DISPATCH] high-1 | ENA  | model=deepseek/deepseek-v4-flash
23:46:12 [DISPATCH] high-1 | ESP  | model=deepseek/deepseek-v4-flash
23:46:12 [DISPATCH] high-1 | GIGGLE | model=deepseek/deepseek-v4-flash
23:46:12 [DISPATCH] high-1 | GMT  | model=deepseek/deepseek-v4-flash
23:46:27 [ERROR] cron add 失败 × 6
```

## 根因：两个 Bug 叠加

### Bug 1 — `importCronJobs()` 删除 internal 条目导致任务"蒸发"

旧逻辑：
1. `importCronJobs` 第 N 次运行：缓存中有 BILL/CHZ → 删除其 `internal:` 条目 → 添加 `cron:` 条目
2. BILL/CHZ 执行完毕 → `delete-after-run` 从 cron 中删除
3. 缓存刷新 → BILL/CHZ 不在输出中
4. `importCronJobs` 第 N+1 次运行：清除所有 `cron:` 条目（BILL/CHZ 的被删）→ 缓存中找不到 BILL/CHZ → `internal:` 条目在第 N 次已被删 → **任务从 activeJobs 彻底消失**
5. `computeLoad()` 返回 0，池子看似空

### Bug 2 — `schedulerTick` while 循环同一 tick 内批量派发

旧逻辑：
1. `executeCronAdd()` 用 `spawn` 异步执行 `openclaw cron add`
2. `activeJobs` 条目在 spawn 回调中写入（异步）
3. while 循环不等待回调，继续检查下一个任务
4. `computeLoad()` 看不到刚派发的任务 → 认为槽位仍然空闲
5. 6 个任务在同一个 tick 内全部派发

### 叠加效果

Bug 1 让池子负载归零 → Bug 2 让所有排队任务一口气放出去。

## 修复

### Bug 1 修复：不再删除 internal 条目，改为 computeLoad 去重

- `importCronJobs()` 注释掉 `activeJobs.delete('internal:' + job.name)`
- `computeLoad()` 增加按 `name` 字段去重：同一任务名在 internal 和 cron 条目中只计一次
- cron 条目增加 `name` 字段（从 `job.name` 获取）

### Bug 2 修复：派发时同步写入 activeJobs

- `executeCronAdd()` 派发前同步写入 `activeJobs`（`source: 'dispatch-pending'`）
- spawn 回调成功：删除 pending 条目，替换为 `internal` 条目
- spawn 回调失败或异常：删除 pending 条目
- `importCronJobs()` 顺便清理过期的 `dispatch-pending` 条目

## 修改文件

| 文件 | 改动 |
|------|------|
| `scripts/cron-dispatcher.js` | Bug1: importCronJobs 不删 internal + computeLoad 去重 + cron 条目加 name 字段 |
| `scripts/cron-dispatcher.js` | Bug2: executeCronAdd 同步写 pending 条目 + 回调清理 |

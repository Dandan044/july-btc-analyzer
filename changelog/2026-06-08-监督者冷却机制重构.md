# [2026-06-08] 监督者 BLOCK 冷却机制重构：从 nohup sleep 到 cooldown-timer 警报规则

## 背景

监督者驳回（BLOCK）开仓决策后，系统需要等待一段冷却期（30m/1h/2h）再触发重分析。原机制使用 `nohup bash -c "sleep N && ..."` 做延迟触发，存在两个严重问题：

1. **可靠性差**：WSL 重启、进程被杀、OOM 都会导致延迟触发器丢失，被驳回的周期永久失去重分析机会
2. **Dashboard 误报**：监督者 BLOCK 后执行 `archive-rules.js --coin {COIN}` 全量归档规则，冷却期间该币种无任何活跃规则，Dashboard 显示为"缺规则"——与管道崩溃的症状完全一致，无法区分

同时发现一个提示词 bug：`modules/05-警报决策.md` 中 `ruleType` 描述性文字导致 LLM 在 `alert-candidates.json` 中输出了 `"rule_type"` 而非 `"type"`，stage4 脚本识别为 `undefined`，生成的规则文件类型错误且价位全部丢失。

## 症状

- 监督者 BLOCK 后周期无规则 → Dashboard 13 个币种显示缺规则
- SPACE 币种生成 `SPACE-undefined.js`，price-levels 规则降级为 oi-monitor，价位数据丢失
- BEAT 币种 11 天内累积 58 条归档规则，其中 11 条来自监督者 BLOCK（跨 5 次事件）
- ATH/GALA/SHIB 三个周期的 LLM 会话被派发但从未完成管道，周期目录空挂
- `/api/report` 端点 `path.resolve(filePath)` 相对于 CWD 解析，Dashboard 审查记录子卡片全部 404

## 根因分析

| 问题 | 根因 | 证据 |
|------|------|------|
| 延迟触发脆弱 | `nohup sleep` 无持久化，重启丢失 | `tasks/supervisor-review.md` step 3 |
| 冷却期无规则 | 监督者 BLOCK 全量归档规则，无可感知的冷却标记 | `archive-rules.js --coin {COIN}` |
| `undefined.js` | `05-警报决策.md` 描述性 `ruleType` 被 LLM 当成 JSON key | `SPACE` alert-candidates 中 `"rule_type": "price_levels"` |
| 审查记录 404 | `/api/report` 用 `path.resolve(filePath)` 而非 `path.resolve(BASE_DIR, filePath)` | `server.js:2833` |
| 周期卡住 | LLM 会话超时/崩溃，管道中断无恢复 | ATH/GALA/SHIB 日志停在 stage1→stage2 |
